> 编写日期: 2026-05-07  
> 最后更新: 2026-05-07  
> 当前版本基线: 单体 CRUD + 禁忌搜索排样 + RBAC  
> 目标: 从"工具"演进为"平台"

---

## 一、现状诊断

| 维度 | 现状 | 痛点 |
| --- | --- | --- |
| 业务深度 | 订单只有创建/查询，无生命周期 | 无法追踪订单执行进度 |
| 权限模型 | ~~单一 JWT 认证，无角色区分~~ ✅ 已解决 | 工人/主管/管理员同权 |
| 可视化 | Dashboard 仅 3 个数字卡片 | 无图表、无趋势、无 KPI |
| 算法 | 单一禁忌搜索，同步阻塞 | 无算法对比、无异步执行 |
| 数据链路 | 排样结果与生产执行割裂 | 排了但不知道切没切 |
| 运维 | 无容器化、无监控 | 部署靠手动，排错靠日志 |
| 集成 | 零外部对接 | 无法对接 ERP / CAD |

## 三、分阶段详细方案

### ① 基础架构加固

**RBAC 权限体系** ✅ 已完成 (2026-05-07)
- ~~引入 Spring Security~~ → 实际采用轻量增强方案：在现有 JWT + TokenInterceptor 基础上扩展
- 角色: admin / operator / viewer（三角色）
- 权限码: `user:manage` `customer:read/write` `board:read/write` `order:read/write` `algorithm:execute` `layout:read`
- 后端: `@RequirePermission` 注解 + TokenInterceptor 校验
- 前端: `v-permission` 指令 + 权限感知导航
- 数据库: `t_role` `t_permission` `t_user_role` `t_role_permission` 四张表
- 提交: `a415637` feat(rbac): 实现基于角色的权限控制模块

**操作审计日志** ✅ 已完成 (2026-05-07)
- 记录: 操作人/模块/动作/参数/IP/耗时/结果
- 基于 AOP `@AuditLog` 环绕通知 + `@Async` 异步写入，不阻塞主业务
- 前端: 日志分页列表，支持按模块/操作人/状态筛选
- 注解覆盖 7 个控制器的所有写操作（增/删/改/启禁/分配角色）
- 提交: 待提交

**数据导入导出**
- Excel 批量导入客户/板材/订单
- 排样结果导出为 PDF 标签 / Excel 清单
- 技术: Apache POI / EasyExcel, iText

**全局文件管理**
- 板材照片、订单附件、设计图纸上传
- 技术: MinIO (自建对象存储) 或阿里云 OSS

---

### ② 业务深化 & 生产管理

**订单生命周期**
```
待审核 → 已审核 → 排样中 → 已排样 → 生产中 → 已完工 → 已交付
  ↓        ↓        ↓        ↓        ↓         ↓        ↓
 驳回     取消     排样失败   重新排样  暂停      返工
```
- 状态流转由后端状态机控制（建议用 Spring State Machine 或枚举守卫）
- 每个节点记录操作人 + 时间戳

**生产任务模块**
- 排样结果确认后生成"切割任务"
- 任务支持分配工人、预估工时、实际工时
- 任务看板（Kanban）: 待生产 / 生产中 / 已完成
- 关键: 打通"排样 → 执行"的数据断层

**余料智能管理**
- 余料自动登记（切割后剩余板材）
- 余料推荐：新订单排样时优先匹配合适余料
- 余料利用率统计，低利用率告警

**质量管理**
- 质检记录（合格/不合格/返工原因）
- 不良品率统计，按板材类型、按工人维度分析
- 技术: 关联切割任务 + 质检拍照留证

**成本核算**
- 板材成本、人工成本、损耗成本
- 按订单/客户/时间段核算利润
- 毛利率、材料利用率双维度评价

---

### ③ 算法升级 & 智能优化

**多算法并行 & 对比**
- 新增: 遗传算法 (GA)、贪心 + 局部搜索、Guillotine 剪切算法
- 算法策略模式统一接口，前端可选算法并对比结果
- 技术: 策略模式 `CuttingAlgorithm` 接口，多实现注入

**异步求解 & 任务队列**
- 复杂排样耗时可能超过 HTTP 超时上限
- 提交排样任务 → 返回 taskId → 轮询 / WebSocket 推送结果
- 技术: Spring `@Async` + `CompletableFuture`，或引入轻量消息队列

**AI 辅助推荐**
- 基于历史排样数据，推荐板材规格组合
- 预测新订单的材料利用率区间
- 技术: 简单的 ML 模型 (Smile / DJL) 或规则引擎

**3D 排样预览**
- 前端 Three.js 渲染排样结果，支持旋转/缩放
- 板材利用率热力图（颜色标识高/低利用率区域）
- 技术: Three.js + Canvas 2D 降级方案

**排样 "断点续排"**
- 人工拖拽微调排样结果
- 锁定部分矩形后重新排样
- 技术: 前端 Canvas 交互 + 增量算法求解

---

### ④ 数据分析 & 可视化

**实时看板**
- 今日订单数、切割任务完成率、材料利用率、不良品率
- 近 7/30 天趋势折线图
- 技术: ECharts (vue-echarts) / AntV G2

**报表中心**
- 日报: 当日切割任务汇总
- 周报/月报: 材料利用率趋势、成本分析
- 支持 PDF 导出
- 技术: JasperReports 或前端 `html2canvas` + `jspdf`

**数据大屏**
- 独立全屏页面，适合车间电视/大屏展示
- 实时刷新关键指标
- 技术: DataV 风格布局 + ECharts + WebSocket 数据推送

---

### ⑤ 移动端 & 现场体验

**小程序增强**
- 扫码开工：工人扫描任务二维码，一键上报切割进度
- 拍照上传：切割结果、余料、不良品拍照留证
- 离线缓存：现场网络不稳定时本地缓存，恢复后同步
- 消息推送：新任务分配通知、质检不通过提醒

**PWA 网页端**
- 网页端支持 PWA，可在移动浏览器安装到桌面
- Service Worker 缓存静态资源，弱网可用
- 技术: `vite-plugin-pwa`

**二维码 / 条形码**
- 为订单、任务、板材生成唯一二维码
- 打印后贴在生产现场，扫码快速定位
- 技术: ZXing (后端生成) / `qrcode` (前端生成)

---

### ⑥ 系统集成 & DevOps

**容器化部署**
- Docker Compose 一键部署（后端 + MySQL + MinIO + Nginx）
- 多环境配置分离 (dev / test / prod)
- 技术: Docker, Docker Compose, Nginx 反向代理

**CAD 文件对接**
- 导入 DXF/DWG 文件，自动解析切割形状
- 技术: `kabeja` (Java DXF 解析库) 或在线转换 API

**ERP / MES 接口**
- 提供标准 REST API 供外部系统调用
- API Key 认证，请求签名验证
- Webhook 回调：订单状态变更时通知 ERP

**消息通知中心**
- 站内信、邮件、微信小程序订阅消息
- 技术: Spring Event + 策略模式多通道分发

**搜索引擎**
- 板材/订单/客户模糊搜索、拼音搜索
- 技术: Elasticsearch 索引同步（Canal 或定时任务）

## 七、风险 & 取舍

| 风险 | 应对 |
| --- | --- |
| 过度设计 | 第 1 批先做 RBAC + Docker，验证模块拆分可行性后再展开 |
| 算法异步化复杂度 | 先用 `@Async` + 轮询，量大再引入消息队列 |
| 小程序审核 | 扫码/拍照功能可先做网页端，小程序渐进增强 |
| Elasticsearch 运维成本 | 初期用 MySQL 全文索引 + 前端本地搜索兜底，ES 按需引入 |
| 3D 可视化投入产出 | Canvas 2D 已能满足生产需求，Three.js 作为增强选项，不做硬性依赖 |
