7 结论
　　本文围绕柜门板材切割排版业务展开研究，针对人工排版过程中存在的数据分散、重复录入、排样效率较低和结果不便追溯等问题，设计并实现了一套基于 Spring Boot 的柜门板材切割排版系统。系统以柜门板材加工流程为基础，将客户资料、板材规格、订单板件、排样参数、算法结果和生产任务等内容纳入统一管理，使排样计算不再只是单独的算法操作，而是能够与业务数据录入和结果保存形成连续流程。
　　在系统功能实现方面，后端采用 Spring Boot、MyBatis-Plus 和 MySQL 完成接口开发与数据存储，主要实现了用户登录与角色权限控制、多组织数据隔离、客户管理、板材管理、订单管理与订单生命周期状态机、排样结果保存、生产任务管理与看板展示、审计日志以及柜体设计与订单拆分等功能。系统采用基于角色的访问控制机制，定义了系统管理员、组织管理员、操作员和生产员四种角色，通过权限编码对各功能模块进行细粒度权限控制，并通过租户拦截器实现组织级数据隔离。前端采用 Vue 3、Element Plus 和 Canvas 2D 完成页面交互与图形展示，并集成Three.js实现三维柜体设计工作台。用户可以在网页端完成柜体设计、板材选择、板件尺寸录入、参数设置和排样结果查看。通过前后端接口交互，系统能够将用户录入的加工数据转换为算法输入，并将算法输出的板材利用率、板件坐标和旋转状态返回给前端进行展示。
　　在排样算法方面，本文采用禁忌搜索与天际线放置算法相结合的方式进行求解。禁忌搜索用于调整板件的排列顺序，避免算法在较短时间内反复搜索相似方案；天际线放置算法用于根据当前排列顺序计算具体坐标，并在放置过程中检查边界、间隙、旋转和重叠约束。当单张板材无法完成全部排样时，系统会将已放置板件移除，并对剩余板件继续进行多容器排样。该方案虽然不能保证得到全局最优解，但实现过程较清晰，计算结果也便于转换为前端 Canvas 图形，适合本系统的工程实现需求。
　　在系统测试方面，本文使用 ApiFox 对登录认证、权限控制、多组织数据隔离、客户管理、板材管理、排样参数提交、排样结果返回、生产任务管理和柜体设计等接口进行了测试，并通过 Chrome 浏览器检查前端页面展示和交互效果。测试结果表明，系统能够完成主要业务流程，不同角色用户的权限控制和组织级数据隔离能够正常生效，生产任务的创建、分配和状态流转功能运行正常，柜体模板管理和订单拆分流程可以正确执行。接口返回结构较统一，排样结果能够以表格和图形方式展示。对于错误密码、空参数、无权限访问和非法状态跳转等异常场景，系统也能够返回相应提示。
　　由于开发周期和测试条件有限，系统仍存在一些不足。首先，当前排样算法主要针对规则矩形板件，对异形板件、纹理方向强约束和复杂余料优先策略支持还不够充分。其次，测试数据规模相对有限，对大批量订单、多种板材混合使用和高并发访问等情况验证不足。再次，三维柜体设计模块在复杂柜体场景下的渲染性能和交互流畅度仍有优化空间，板材数量较多时可能出现卡顿。最后，系统在排样结果导出和历史方案对比方面仍有进一步完善空间。后续研究可以从算法优化、余料复用、导出功能、三维渲染性能优化和生产流程管理等方面继续改进，使系统更接近实际柜门加工场景中的长期使用需求。
