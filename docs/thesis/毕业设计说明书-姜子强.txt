摘要
　　针对柜门板材加工过程中存在的下料数据管理分散、人工排版效率低、板材利用率不稳定以及排样结果难以追溯等问题，本文设计了一套基于Spring Boot的柜门板材切割排版系统，实现了从基础资料维护、加工数据录入、算法排样、结果展示到生产任务管理的完整业务流程。该系统采用Spring Boot、MyBatis-Plus和MySQL构建后端服务，使用JWT与拦截器实现用户认证和接口访问控制；网页端基于Vue 3、Vite、Pinia、Element Plus与Canvas 2D实现后台管理、加工数据录入和排样结果可视化。系统实现的主要功能包括用户认证、客户管理、板材管理、订单管理、订单明细管理、余料管理、排样结果管理、生产任务管理和排样算法求解等。
　　本文创新地将生产业务管理与智能排样算法相结合，实现了面向实际柜门板材加工场景构建了一套可落地的排样求解流程。本文设计了基于“禁忌搜索+天际线放置算法”的组合排样策略。算法以矩形工件的排列顺序作为搜索对象，通过随机交换生成邻域解，并利用禁忌表记录已访问状态，降低搜索陷入局部最优的风险。在候选解评价阶段，系统采用天际线算法完成具体放置过程：根据板材剩余可用轮廓维护天际线线段，依次判断工件在原始方向和旋转方向下是否满足边界、间距和尺寸约束，并优先选择高度较低、位置靠左的放置点，从而提高空间利用率和排样紧凑性。此外，本文在算法实现中引入了多容器循环求解机制，并支持工件旋转控制、板件间距约束、利用率计算和排样坐标输出，使排样结果既能满足加工约束，又能直接用于前端Canvas可视化展示和后续结果持久化。
　　系统测试方面，本文主要使用ApiFox对系统中的用户登录、客户管理、板材管理、排样参数提交以及排样结果返回等核心接口进行了测试。同时，本文也通过Chrome浏览器对Vue前端页面的展示效果和交互过程进行了辅助验证。测试结果显示，系统可以较为正确地完成用户登录鉴权、基础资料维护、排样参数校验、算法请求处理和排样结果返回等主要功能。各接口的响应结构比较清楚，业务数据能够正常返回，前端页面也可以根据接口返回结果完成表格数据展示和Canvas排样图绘制。总体来说，本系统在测试过程中运行比较稳定，基本能够满足柜门板材切割排版业务的实际使用需求。
关键词：板材切割；多容器排样；禁忌搜索；Spring Boot；Vue 3

Abstract
　　To solve some problems in cabinet door panel processing, such as scattered cutting data management, low efficiency of manual layout, unstable board utilization rate, and difficult tracing of layout results, this thesis designs and implements a cabinet door panel cutting layout system based on Spring Boot. The system covers the main business process, including basic data maintenance, processing data input, algorithm layout, result display, and production task management. The backend uses Spring Boot, MyBatis-Plus, and MySQL, and adopts JWT and interceptors to realize user authentication and interface access control. The frontend is developed with Vue 3, Vite, Pinia, Element Plus, and Canvas 2D, supporting backend management, data input, and layout result visualization. The main modules include user authentication, customer management, board management, order management, leftover material management, layout result management, production task management, and layout algorithm solving.
　　The main innovation of this thesis is to combine production business management with intelligent layout algorithm for cabinet door panel processing. A hybrid layout strategy based on tabu search and skyline placement algorithm is designed. Tabu search is used to optimize the placing order of rectangular workpieces, generate neighborhood solutions by random exchange, and use a tabu list to avoid local optimum. During evaluation, the skyline algorithm maintains available board segments, checks placement feasibility under boundary, spacing, size, and rotation constraints, and selects lower and more left positions as far as possible to improve layout compactness and material utilization. A multi-container solving mechanism is also introduced, which supports rotation control, gap constraint, utilization rate calculation, and coordinate output, so that the layout results can be used for Canvas visualization and result persistence.
　　For system testing, this thesis uses ApiFox to test core interfaces such as user login, customer management, board management, layout parameter submission, and layout result return. Chrome browser is used to verify the display and interaction of Vue frontend pages. The test results show that the system can correctly complete user authentication, basic data maintenance, parameter validation, algorithm request processing, and layout result return. The interface structure is relatively clear, business data can be returned correctly, and the frontend can display tables and draw layout diagrams through Canvas. Overall, the system runs relatively stably and can basically meet the use requirements of cabinet door panel cutting layout business.
　　Key Words: Panel Cutting; Multi-Container Layout; Tabu Search; Skyline Algorithm; Spring Boot; Vue 3

1 引言
1.1 课题研究的背景
　　柜门、橱柜门板及其他定制板材在正式加工前，需要根据客户订单尺寸完成切割排版。该过程不仅涉及待切矩形尺寸的排列，还需记录客户信息记录、原料板规格选择、锯路损耗、安全间距、余料控制以及生产核对等环节密切相关[1,2,3,4]。对于中小型柜门加工企业而言，排版工作往往仍依赖人工经验、纸质单据或电子表格完成。该方式在订单量较小时较为灵活，但当订单尺寸复杂、数量增加或交付周期较紧时，人工排版的效率和准确性便难以稳定保证。随着企业信息化程度的提高，越来越多传统加工业务开始尝试通过管理系统和智能算法提高生产效率[2,3]。在柜门板材切割场景中，如果能够把客户信息、板材规格、尺寸数据录入以及排样计算等内容放在同一个系统中进行管理，就可以在一定程度上减少重复录入的问题，提高数据的一致性，同时也能够为后续生产提供更加直观的排版参考[2,4]。因此，开发一套面向柜门板材切割业务的排版系统具有一定的现实意义和应用价值。
　　在实际加工场景中，人工排版存在几个较为突出的痛点。首先，板材利用率受人工经验影响明显，容易造成较多余料浪费[4]。其次，批量订单需要反复核对尺寸、板材规格和间隙要求，计算过程耗时较长[1,3]。再次，柜门加工对尺寸精度要求较高，如果锯路宽度、安全间距等因素没有被准确考虑，可能导致成品尺寸偏差，增加返工风险[1]。由此可见，板材切割排版并不是单纯的图形排列问题，而是一个同时涉及业务数据管理、算法计算和结果展示的综合性问题[2][4]。
　　从研究对象看，板材切割排样属于切割与装箱问题的典型应用，具有组合优化特征[5]。早期研究主要从一维下料和线性规划模型出发，经典切割库存问题建模方法为后续板材切割优化研究奠定了理论基础[6]。随后，相关研究逐步扩展到二维矩形装箱、二维板材下料和二维带状装箱等问题。已有分类研究和综述研究表明，该类问题在理论上具有较高复杂度，实际生产中通常需要结合启发式策略求解[5,7]。
1.2 课题研究的发展现状
　　从算法发展现状看，二维矩形排样问题的求解方法大体可以分为精确算法、构造型启发式算法和元启发式算法[8,9]。精确算法能够在小规模实例中获得较优解，但随着工件数量增加，搜索空间迅速扩大，难以满足生产现场对计算速度的要求[8]。启发式算法通过规则快速生成可行解，适合工程应用，但容易受到输入顺序和局部选择规则影响[8][9]。元启发式算法则通过模拟搜索、进化或记忆机制扩大寻优范围，其中禁忌搜索利用禁忌表避免重复搜索和局部循环，在组合优化问题中具有较强适用性[9,10]。相关综述表明，遗传算法、模拟退火、禁忌搜索等方法已被广泛用于二维排样问题[9,10]；后续研究也将禁忌搜索、遗传算法等方法应用于二维非切割式下料和二维带状排样问题，验证了元启发式方法在提高排样质量方面的价值[11]。
　　从具体放置策略看，二维矩形排样通常需要先确定工件排列顺序，再依据一定规则计算每个矩形的放置坐标。常见策略包括左下角法、最低水平线法、剩余矩形法和天际线法等[12,13,14]。相比简单的逐行放置方法，天际线法通过维护板材当前已占用区域上方的轮廓线，能够更细致地描述剩余可用空间，并在每次放置后动态更新可放置线段。相关天际线启发式研究在二维矩形装箱和带状装箱问题中表现出较好的效率和装填效果[14]。因此，在柜门板材加工这类以矩形工件为主、需要输出具体坐标的场景中，天际线法具有较好的工程适配性。
　　从国内应用与工程实现看，近年来相关研究开始更多关注混合启发式算法和实际生产约束。国内学者针对大规模矩形件排样、遗传算法与禁忌搜索混合优化、遗传蚁群算法等方向开展了研究，试图在计算效率和材料利用率之间取得平衡[1,11,13,15]。但在中小型柜门加工企业的实际场景中，排样算法往往仍与客户、板材、订单、余料和结果追踪等业务流程分离，导致算法结果难以直接沉淀为生产数据[2,16]。基于上述现状，本文在系统设计中不仅关注排样算法本身，还将客户管理、板材管理、尺寸录入、算法求解和结果可视化整合到统一平台中，并采用“禁忌搜索+天际线放置算法”的组合策略，使系统既能满足基础业务管理需求，又能在一定程度上提高排样自动化水平和板材利用率。
1.3 课题研究的目的和意义
　　本文课题的主要目的是设计并实现一套基于Spring Boot的柜门板材切割排版系统，使系统能够完成客户管理、板材管理、尺寸录入、排样计算和结果展示等基本业务流程。系统通过后端接口对业务数据和算法请求进行统一处理，并通过 Vue 前端提供较为轻量的交互页面，使用户可以完成排样参数的录入，并查看系统计算得到的排样结果。
　　本课题的实际意义主要体现在以下几个方面。第一，系统通过禁忌搜索算法与天际线放置算法生成排样结果，在一定程度上有助于提高板材空间利用率，减少材料浪费。第二，系统可以减少人工录入和人工排版的工作量，使客户信息、板材信息和待切割尺寸能够以结构化的方式进行保存，从而降低漏录、错录和重复录入等问题出现的可能。第三，系统提供排样结果表格和图形化展示功能，使用户能够更加直观地查看矩形板件在原料板中的具体放置位置，便于后续生产过程中的核对和使用。
1.4 课题研究的主要内容
　　本文围绕柜门板材切割排版系统的设计与实现展开，主要研究内容分为如下四个部分：
　　（1） 分析柜门板材切割业务需求，明确系统用户在客户管理、板材管理、尺寸录入、排样计算和结果查看等方面的功能需求，并结合实际加工场景确定系统的基本业务流程。
　　（2） 完成系统技术方案设计。系统后端采用Java语言和Spring Boot框架进行开发，结合MyBatis-Plus实现数据访问，使用MySQL存储业务数据，并通过JWT实现登录鉴权。前端采用Vue 3技术栈构建交互界面，满足后台管理、数据录入和排样结果查看需求。
   （3） 设计并实现排样算法模块。当前系统采用“禁忌搜索+天际线放置算法”的启发式方案。天际线算法用于计算矩形在板材中的具体放置位置，禁忌搜索用于调整矩形排列顺序，从而寻找空间利用率更高的排样结果。算法同时支持矩形90度旋转、间隙距离设置和多容器迭代求解。
　　（4） 完成系统主要功能实现与测试。系统实现了登录鉴权、客户信息管理、板材信息管理、算法接口调用、Vue页面交互和排样结果可视化等功能，并通过ApiFox接口测试验证系统的可用性。

2 相关技术介绍
2.1 Spring Boot
　　本系统后端采用Spring Boot框架进行开发。Spring Boot是在Spring生态基础上形成的快速开发框架，能够通过自动配置、内嵌服务器和统一依赖管理简化Java Web项目的搭建过程。与传统Spring项目相比，Spring Boot减少了大量XML配置和重复性工程配置，适合在毕业设计系统中快速完成接口服务、业务模块和测试环境的构建。
　　在本系统中，Spring Boot主要承担后端基础框架作用。系统通过Spring Web提供RESTful接口，对外支持用户登录、客户管理、板材管理、订单管理和排样算法求解等功能。Vue前端通过HTTP请求调用后端接口，后端完成参数校验、业务处理、数据访问和算法调用后，将处理结果以统一JSON格式返回给前端。采用这种方式可以使业务逻辑集中在后端实现，前端主要负责页面展示和用户交互，从而提高系统结构的清晰性和后续扩展能力。
2.2 MyBatis-Plus
　　系统持久层采用 MyBatis-Plus 完成数据库访问。柜门板材切割排版系统中存在大量基础数据维护操作，例如客户资料、板材规格、订单信息和排样结果的新增、查询、修改和删除。如果每个模块都重复编写基础 SQL，会增加代码量，也不利于后期维护。MyBatis-Plus 提供的通用 CRUD、条件构造器和分页查询功能，可以较好地适配这类后台管理场景。
　　在本系统中，MyBatis-Plus 主要用于实体类与数据库表之间的映射。客户管理和板材管理模块通过 Mapper 接口完成列表查询、条件筛选和状态更新；订单模块通过订单表和订单明细表保存待切割板件数据；排样结果模块则将算法返回的利用率、板材数量和坐标结果保存到数据库中。对于按客户名称、板材材质、颜色、状态等条件筛选的数据，系统可通过条件构造器动态生成查询条件，从而避免在代码中编写大量重复判断。
2.3 MySQL数据库
　　本系统选用 MySQL 作为关系型数据库，用于保存用户、客户、板材、订单、订单明细、余料和排样结果等数据。柜门板材切割排版业务具有较明显的关联关系，例如一个客户可以对应多个订单，一个订单可以包含多条板件明细，一次排样结果又需要关联到具体订单。因此，采用关系型数据库可以较清楚地表达这些业务关系，并通过主键、外键和唯一约束保证数据的一致性。
　　在数据库设计中，订单数据是系统的核心。客户表保存客户基础资料，板材表保存原料板材规格，订单表保存客户快照、订单状态和排样参数，订单明细表保存待切割板件的尺寸、数量、材质和旋转要求，排样结果表保存算法计算后的利用率、坐标数据和板材使用数量。对于排样参数和算法输出结果这类结构变化较大的数据，系统采用 JSON 字段保存，以便在不频繁修改表结构的情况下扩展后续功能。
2.4 JWT身份认证
　　由于本系统采用前后端分离结构，前端页面和后端接口之间通过 HTTP 请求进行交互。为了避免用户在未登录状态下访问客户、板材、订单和排样计算等业务接口，系统采用 JWT 完成登录鉴权。用户登录成功后，后端根据用户信息生成 token 并返回给前端，前端在后续请求中将 token 放入请求头，后端拦截器再对 token 进行解析和校验。
　　在系统实现中，JWT 主要用于解决接口访问权限问题。登录接口不需要携带 token，而客户管理、板材管理、订单管理和排样算法调用等接口都需要经过拦截器校验。若 token 缺失、过期或解析失败，系统会返回未授权提示；若 token 校验通过，后端再继续执行对应业务逻辑。这样既能减少服务器端保存会话状态的压力，也能较好地适应 Vue 前端与 Spring Boot 后端分离部署的场景。
2.5 B/S架构与前后端分离
　　本系统采用 B/S 架构，用户通过浏览器访问前端页面，不需要单独安装客户端软件。对于中小型柜门加工场景而言，浏览器访问方式更便于部署和使用，后期如果需要在车间电脑或办公电脑上使用系统，也只需要保证网络和浏览器环境即可。
　　在前后端分离模式下，前端主要负责页面展示、表单输入和排样结果绘制；后端主要负责身份认证、业务处理、数据库访问和排样算法调用。以前端的排版工作台为例，用户在页面中录入板材尺寸、板件尺寸、旋转设置和切割间隙后，前端通过 Axios 将参数提交到后端接口。后端完成参数校验和算法计算后，返回板材利用率、板件坐标和旋转状态等数据，前端再使用 Canvas 进行图形化展示。这样的结构使页面交互和业务计算相互分离，便于分别调试和维护。
2.6 Vue 3、Vite与Element Plus
　　网页端采用Vue 3和Vite技术栈。Vue 3是渐进式JavaScript框架，适合构建交互式单页应用，其组合式API有利于组织页面状态、接口调用和复用逻辑。Vite是前端构建工具，具有启动速度快、热更新及时和配置简洁等特点，适合在开发阶段提高网页端调试效率。
　　网页端界面层使用Element Plus组件库。Element Plus提供表格、表单、弹窗、按钮、分页和提示信息等常用后台管理组件，有助于统一页面风格并降低界面开发成本。在本系统中，网页端主要用于客户管理、板材管理、订单管理、排样参数输入和排样结果查看等功能。针对排样结果可视化，系统结合Canvas 2D绘制板材矩形、工件色块和排版布局，使用户能够直观查看每块板件在原料板中的位置和尺寸。
2.7 Vue前端
　　Vue 前端是用户直接操作系统的入口，主要面向后台管理和加工数据录入场景。用户登录后，可以进入客户管理和板材管理页面维护基础资料，也可以在订单和加工数据页面中录入待切割板件信息。对于排样结果，前端既需要显示板材利用率、板材数量、板件尺寸和坐标等表格数据，也需要以图形化方式展示板件在原料板中的位置。
　　在排版工作台中，前端通过 Canvas 2D 绘制板材边界和板件矩形。后端返回的每个板件坐标、宽高和旋转状态会被转换为画布中的图形元素，用户可以直观看到板件排列情况。与单纯表格相比，图形化展示更适合排样结果核对，也更接近实际加工人员查看切割方案的习惯。因此，Vue 前端不仅承担数据录入功能，也承担排样结果解释和展示的作用。。
2.8 排样算法
　　柜门板材切割排版问题本质上属于二维矩形排样问题。系统需要在给定原料板材长度、宽度和加工间隙的条件下，将多个柜门板件抽象为待放置矩形，并尽可能紧凑地安排到原料板中。实际加工时，算法不仅要关注板材利用率，还要保证每个矩形位于板材边界以内、板件之间不发生重叠，并为锯路或安全加工距离预留间隙。因此，该问题不是简单的尺寸录入问题，而是同时包含空间约束、顺序优化和坐标输出的组合优化问题。随着待排矩形数量增加，可能的排列组合数量会迅速增大，若直接采用穷举方式求解，计算量会很快超过系统实时交互能够接受的范围。
　　常见排样算法包括精确算法、遗传算法、模拟退火算法、蚁群算法、禁忌搜索算法以及天际线算法等。精确算法能够在小规模数据下获得较优解，但计算复杂度较高，不适合现场快速排版和移动端交互场景。遗传算法、蚁群算法等群智能算法具有较强的全局搜索能力，但参数较多，调试成本较高，且在毕业设计系统中会增加实现复杂度。天际线算法实现相对清晰，能够较快给出矩形放置坐标，适合将结果展示在canvas图形中；但如果仅使用天际线算法，其排样质量容易受到输入矩形顺序影响。相关算法差异如下表 21。
表 21算法差异
算法方案优点不足是否采用穷举/精确算法理论结果较优计算量大，难以适配实时系统否遗传算法全局搜索能力较强参数较多，收敛过程不稳定否蚁群算法适合路径类组合优化矩形坐标防止结合较复杂否天际线算法放置速度快，坐标结果直观手矩形顺序影响明显单独使用不足禁忌搜索+天际线算法兼顾顺序优化和坐标放置，适合工程实现不能保证全局最优采用　　综合系统实时性、实现复杂度和排样效果等因素，本文采用“禁忌搜索 + 天际线放置算法”的组合方案。其中，天际线算法负责在给定矩形顺序下计算具体放置坐标，便于排样结果直接转换为前端图形；禁忌搜索算法负责优化矩形排列顺序，通过生成候选排列并记录已访问状态，减少重复搜索，从而寻找板材利用率更高的排样方案。该方案能够兼顾响应速度、实现难度和排样效果，并便于结合旋转、间隙距离和多板材求解等业务约束。
　　从业务建模角度看，原料板材可抽象为矩形容器，客户订单中的柜门板件可抽象为待切割矩形。系统输入的板材长宽对应容器尺寸，板件长宽和编号对应矩形参数，是否允许旋转用于表示板件能否进行90度方向调整，间隙距离用于表示锯路宽度、安全间距或加工余量。通过这种建模方式，用户录入的板材规格和下料尺寸可以直接转换为算法可处理的数据结构。
　　算法执行过程主要包括数据准备、单板排样和多板处理三个阶段。首先，用户在Vue前端录入板材尺寸、板件尺寸、旋转选项和间隙距离，后端将请求数据转换为排样实例。然后，禁忌搜索生成并调整矩形排列顺序，天际线算法根据该顺序依次计算矩形的可放置位置，并优先选择高度较低、位置靠左且满足边界和间隙约束的方案。当一张板材无法放下全部板件时，系统会移除已成功放置的板件，并对剩余板件继续进行下一张板材的求解，直到所有可放置板件处理完成。
　　该组合算法较好地适配了柜门板材切割场景。柜门板件通常具有规则矩形特征，排样结果不仅需要较高的板材利用率，还需要明确给出每块板件在原料板上的坐标和尺寸，便于前端绘制排版图并供加工人员核对。系统返回的板材尺寸、空间利用率、已放置矩形坐标和尺寸等信息，可以支持排样结果可视化展示，也为后续生产核对、余料管理和历史方案保存提供数据基础。因此，本文选择该组合算法并不是单纯追求理论最优，而是在排样效率、结果可解释性和工程实现复杂度之间进行综合权衡。
2.9 开发环境与工具
　　本系统开发环境分为后端、数据库、前端和测试四个部分。后端使用Java 17、Spring Boot 3.5和Maven完成服务搭建、依赖管理和接口开发；数据库使用MySQL8.0保存用户、客户、板材、订单、订单明细和排样结果等数据；前端使用Vue 3、Vite、Pinia、Vue Router、Axios和Element Plus完成页面开发与接口调用；排样结果绘制部分使用Canvas 2D完成板材和板件图形展示。

3.1.3 功能需求
　　系统面向管理员和生产操作员两类核心用户，划分为四个功能模块。
　　（1）用户认证与基础数据管理。用户注册、登录、登出，基于JWT的无状态认证，受保护接口须携带Token。客户信息与板材规格的增删改查、分页查询及批量启用/禁用/删除。用户账号管理与启用控制。
　　（2）订单管理。订单的增删改查与状态流转（待处理→生产中→已完成/已取消），每个订单下挂多个待切割板件明细。订单明细包含产品名称、数量、长宽尺寸、材质、封边要求等字段。
　　（3）切割排版（核心模块）。加工数据输入页：选择订单与板材规格后，在可编辑表格中输入待切割板件数据，支持键盘导航和TSV粘贴；底部实时汇总板件统计信息；确认后一键提交排版计算。排版工作台：左侧展示历史排版记录列表，中央Canvas画布以二维图形渲染排版方案（支持缩放、平移、工件悬停tooltip、多容器标签切换）；工具栏提供参数配置（旋转开关、切割间隙、容器尺寸）、排版触发、结果导出等功能。排版算法引擎：接收容器尺寸与矩形列表，通过禁忌搜索优化排列顺序、天际线算法确定放置坐标；支持旋转与间隙参数；当单容器无法容纳全部板件时自动启用多容器迭代拆分；支持异步提交与多策略对比。
　　（4）余料管理与生产看板。排版完成后自动记录余料信息（尺寸、材质、来源），供后续排版优先复用。从订单创建生产任务，以看板分栏视图展示任务状态与进度，支持状态流转。
3.1.4 非功能需求
　　性能：常规接口响应≤500ms，50件以内排版计算≤30s。
　　安全性：JWT鉴权覆盖所有业务接口，密码BCrypt哈希存储，参数化查询防注入。
　　一致性：接口统一返回{code, msg, data}结构，前端统一处理和展示错误。
　　可维护性：后端Controller-Service-Mapper分层、前端按模块拆分API客户端与组合式函数、数据库变更通过增量迁移脚本管理。算法模块自包含，各子模块（禁忌搜索、天际线放置、禁忌映射树）相互解耦，便于独立调参与测试。
3.2 系统总体设计
　　根据前文的需求分析，柜门板材切割排版系统需要同时完成基础业务数据管理、订单加工数据录入、排样算法计算、结果可视化展示以及生产任务管理等功能。为了使系统结构更加清楚，也方便后续功能扩展，本文采用 B/S 架构和前后端分离的开发模式，将系统整体划分为用户层、前端表现层、后端服务层、排样算法层和数据存储层。用户通过浏览器访问系统前端页面，前端主要负责页面展示、表单输入、排样结果可视化和用户交互；后端主要负责身份认证、业务逻辑处理、数据访问和算法调用；数据库则用于保存用户、客户、板材、订单、订单明细、排样结果、余料和生产任务等业务数据。
　　在系统运行过程中，管理员和生产操作员首先通过登录页面完成身份认证。登录成功后，用户可以在前端页面中维护客户信息和板材信息，也可以创建加工订单，并录入需要切割的板件尺寸。当用户在加工数据输入页面设置板材尺寸、切割间隙、是否允许旋转等排样参数后，前端通过 Axios 向后端发送排样请求，并在请求头中携带 JWT 令牌。后端接收到请求以后，先对参数进行校验，并完成业务数据的转换，然后调用排样算法模块进行计算。
　　排样算法模块主要通过禁忌搜索算法优化板件的排列顺序，并结合天际线放置算法计算板件在原料板中的具体放置坐标。当一张板材不能放下全部板件时，系统会继续采用多容器迭代的方式，对剩余板件继续进行排样。最后，后端将板材利用率、使用板材数量、板件坐标和旋转状态等结果返回给前端。前端再通过表格和 Canvas 图形化方式对排样结果进行展示，并将排样结果保存到数据库中，为后续余料管理和生产任务管理提供一定的数据支持。

3.3 数据库设计
　　数据库是柜门板材切割排版系统保存业务数据、支撑算法调用和实现结果追溯的重要基础。结合系统业务流程，数据库需要对用户账号、客户资料、板材规格、订单信息、待切割板件、余料信息、排样结果、算法任务和生产任务等数据进行统一管理。本文采用MySQL8.0作为系统关系型数据库，数据库名称为board_cutting_db，存储引擎采用InnoDB，以保证事务一致性、外键约束和并发访问能力。数据库字符集采用utf8mb4，以满足中文客户信息、板材名称、备注说明及JSON数据存储需求。
　　在数据库设计过程中，本文遵循以下原则：第一，围绕系统核心业务流程进行建模，使数据表能够支撑客户管理、板材管理、订单录入、排样计算、结果保存和生产任务管理等功能；第二，合理设置主键、外键和唯一约束，保证数据之间的关联完整性；第三，对订单排样参数、算法输出结果等结构变化较大的数据采用JSON字段进行保存，提高系统扩展性；第四，对客户、板材、订单等历史业务数据保留必要快照，避免基础资料后续修改影响历史订单的查询和复核。
3.3.1 数据库需求分析
　　根据柜门板材切割排版系统的功能需求，数据库主要需要满足以下几个方面的数据存储要求。
　　（1）用户与权限数据存储。系统用户需要在登录后，才能进行客户维护、板材维护、订单录入和排样计算等操作，所以数据库需要保存用户账号、密码、联系方式、账号状态和登录时间等信息。为了方便后续扩展系统管理功能，数据库中还预留了角色表、权限表、用户角色关联表和角色权限关联表，用来支持不同类型用户的权限控制。
　　（2）基础业务资料存储。系统需要对客户资料和板材规格信息进行长期维护。客户资料主要包括客户名称、联系电话、地址、启用状态和备注等内容；板材规格信息主要包括品牌、材质、颜色、规格类型、长度、宽度、厚度、使用次数和启用状态等内容。这些数据是后续创建订单、选择原料板材以及调用排样算法的重要基础。
　　（3）订单与板件数据存储。一个客户可以对应多个加工订单，一个订单中也可以包含多个需要切割的柜门板件。订单表主要用于保存订单编号、客户快照、加工名称、订单状态、原料板配置、余料配置和排样参数等信息；订单明细表主要用于保存板件名称、板件编号、尺寸、数量、材质、颜色、封边信息、纹理方向和是否允许旋转等数据。
　　（4）余料与排样结果数据存储。柜门板材在切割之后，可能会产生一些还可以继续利用的余料，所以系统需要记录余料的来源订单、原始板材、尺寸、材质、颜色和使用状态等信息。排样计算完成后，系统还需要保存板材利用率、总切割面积、使用板材数量、排样坐标结果等数据，为后续历史方案查询、生产核对和结果导出提供数据依据。
　　（5）算法任务与生产任务数据存储。在复杂订单中，排样计算可能会花费较长时间，因此数据库需要保存算法任务的输入参数、任务状态、输出结果、最优利用率、容器数量和运行耗时等信息。生产任务表则用于把订单和排样结果进一步转化为生产安排，记录任务名称、负责人、预计工时、实际工时、任务状态、开始时间和完成时间等内容。

4 排样问题建模与算法设计
4.1 排样问题描述
　　柜门板材切割是家具制造中的关键工序。工厂采购的标准板材（如2440mm×1220mm）作为原材料，需要按照订单要求切割出尺寸各异的柜门板件。如何在一块或多块标准板材上合理排布这些板件，使得板材利用率最高、边角料浪费最少，是排样优化的核心问题。
　　将上述实际场景抽象为计算问题：给定一个长度为L、宽度为W的矩形容器，以及n个待排样的矩形工件，第i个工件的长度为l_i、宽度为w_i。允许工件旋转90度（旋转后尺寸变为w_i×l_i），工件之间及工件与容器边界之间需保留最小间隙距离gap。要求确定每个工件在容器中的放置坐标和方向，使得容器内已放置工件的面积之和与容器面积之比（即空间利用率）最大。当单个容器无法容纳全部工件时，系统采用相同规格的多个容器依次排样，最终目标等效为用最少的容器装下全部工件。
　　为了更直观地说明柜门板材切割排样问题，本文将原料板材抽象为二维矩形容器，将客户订单中的柜门板件抽象为待排矩形工件，其建模示意如图4-1所示。
　　
图 41建模示意图
　　该问题的本质是二维矩形装箱问题（2D Rectangular Bin Packing Problem），属于经典的NP-hard组合优化问题。随着矩形数量的增长，解的搜索空间呈指数级膨胀，无法通过穷举法在合理时间内求得精确最优解，因此必须采用启发式或元启发式算法在可接受的时间内逼近较优解。
4.2 排样问题数学模型
　　为便于对柜门板材切割排版问题进行算法求解，本文将实际加工场景抽象为二维矩形装箱问题。该问题是在给定板材尺寸、板件尺寸、切割间隙和旋转规则的条件下，确定各板件在板材中的放置位置与放置方向，使板件完整位于板材范围内，板件之间不发生重叠，并尽可能提高板材利用率。当单张板材无法容纳全部板件时，系统使用多张相同规格的板材完成排样，并以减少板材使用数量作为进一步优化目标。
4.2.1 优化目标
　　（1）最大板材利用率
　　板材利用率表示当前板材中已成功放置板件的面积之和与单张板材面积的比值，其计算公式为：
           　　　　　rate=(∑_(i∈P)?s_i )/S           （4-1）　　其中，P表示当前板材中成功放置的板件集合，s_i表示第i个板件的面积，S表示单张板材面积。单张板材排样时，优化目标为：
           　　　　　max?rate　　（4-2）　　该目标表示在满足边界、不重叠、间隙和旋转规则的前提下，使当前板材中已放置板件的面积占比尽可能高，从而减少板材浪费。
　　（2）最小化板材使用数量
　　当订单板件数量较多，单张板材无法完成全部排样时，系统需要将所有板件分配到多张板材中。设m表示排样过程中使用的板材数量，P_1，P_2，?，P_m分别表示第1张至第m张板材中放置的板件集合，则所有板材上的板件集合应覆盖全部待排样板件：
           　　　　　P_1∪P_2∪?∪P_m={1,2,?"?",n}　　（4-3）　　同时，不同板材之间的板件集合不能重复：
           　　　　　P_a∩P_b=?,a≠b           （4-4）　　在完成全部板件排样的前提下，多板材排样的优化目标为：
           　　　　　min?m           （4-5）　　该目标表示系统应尽可能使用更少数量的板材完成订单排样，以降低原料板材消耗，提高整体加工经济性。
4.2.2 约束条件
　　（1）基本集合与面积约束
　　设原料板材长度为L，宽度为B，则单张板材面积为：
           　　　　　S=L×B           （4-6）　　设待排样板件数量为n，待排样板件集合为：
           　　　　　I={1,2,?,n}           （4-7）　　第i个板件的原始长度为l_i，原始宽度为w_i，则其面积为：
           　　　　　S_i=l_i×w_i           （4-8）　　板件之间以及板件与板材边界之间需要保留最小间隙距离，且间隙距离不能为负数：
           　　　　　gap≥0           （4-9）　　上述约束用于定义排样问题中的基本对象和基础参数，是后续边界约束、不重叠约束和目标函数计算的基础。
　　（2）板件坐标与旋转约束
设第i个板件在板材中的左下角放置坐标为：
           　　　　　(x_i,y_i)           （4-10）设r_i表示第i个板件是否旋转的决策变量：
           　　　　　r_i∈{0,1}           （4-11）当r_i=0时，板件按照原始方向放置；当r_i=1时，板件旋转90°后放置。因此，第i个板件实际放置后的宽度W_i和高度H_i分别为：
           　　　　　W_i=(1-r_i)l_i+r_i w_i           （4-12）           　　　　　H_i=(1-r_i)w_i+r_i l_i           （4-13）若系统设置为不允许板件旋转，则所有板件均满足：
           　　　　　r_i=0,i=1,2,?"?",n           （4-14）该约束用于控制板件是否可以通过旋转改变放置方向，保证排样结果符合实际加工规则。
　　（3）板件边界约束
为保证板件完整位于板材内部，每个已放置板件都必须满足边界约束。板件左下角坐标应与板材左边界和下边界保持最小间隙：
           　　　　　x_i≥gap           （4-15）           　　　　　y_i≥gap           （4-16）板件放置后不能超出板材右边界和上边界，并且应保留最小间隙：
           　　　　　x_i+W_i+gap≤L           （4-17）           　　　　　y_i+H_i+gap≤B           （4-18）上述约束保证板件不会越过原料板材边界，同时为切割加工预留必要的安全距离或锯路距离。
　　（4）板件间不重叠约束
对于同一张板材中的任意两个不同板件i和j，二者必须在水平方向或垂直方向上完全分离。也就是说，板件i位于板件j左侧、板件j位于板件i左侧、板件i位于板件j下方、板件j位于板件i下方四种关系至少满足一种：
           　　　　　x_i+W_i+gap≤x_j∨                      　　　　　x_j+W_j+gap≤x_i∨           （4-19）           　　　　　y_i+H_i+gap≤y_j∨                      　　　　　y_j+H_j+gap≤y_i,i,j∈P,i≠j           该约束保证同一张板材中的任意两个板件不会发生重叠，并且在板件之间保留最小间隙距离。
　　（5）多板材分配约束
　　当单张板材无法容纳全部板件时，系统使用多张相同规格的板材完成排样。多板材分配需要满足式（4-3）和式（4-4）：一方面，所有板材上的板件集合需要覆盖全部待排样板件；另一方面，不同板材之间不能重复放置同一板件。通过该约束，可以保证每个板件只被分配到一张板材中，避免重复排样或漏排。

4.3 排样算法总体框架
　　在完成排样问题数学模型构建后，需要进一步设计适合系统实现的求解框架。由于柜门板材切割排样问题属于二维矩形装箱问题，待排板件数量增加后，可能的排布组合数量会迅速增大，若采用穷举方式寻找最优解，将难以在实际生产场景中满足计算效率要求。因此，本文采用“排列编码+启发式解码+元启发式搜索”的求解框架，将复杂的二维坐标优化问题转化为工件排列顺序优化问题，再通过天际线算法将排列序列解码为具体的排样方案。该思路来源于原方案中对排样问题求解框架的设计，即通过排列编码确定工件放置顺序，再使用天际线算法确定具体坐标，并结合禁忌搜索在排列空间中进行优化。
　　排样算法总体流程如图4-1所示。

图4-1 排样算法流程图
　　算法整体流程可以概括为：首先读取订单中的板件尺寸、数量、板材规格以及排样参数；然后将待排板件转换为工件列表，并构造初始排列；接着通过禁忌搜索不断调整工件排列顺序，对每一个候选排列调用天际线算法进行解码，得到具体的板件坐标、旋转状态和板材利用率；最后根据评价结果选择较优排样方案。当单张板材无法容纳全部板件时，系统将已成功放置的板件从待排列表中移除，并继续使用新的板材对剩余板件进行排样，直至所有板件完成排布或判定存在无法放入板材的异常板件。
4.3.1 排列编码方案
　　在数学模型中，一个完整排样方案需要确定每个板件的放置坐标和旋转状态。如果直接对所有板件的坐标进行搜索，搜索空间较大，且需要频繁处理复杂的边界约束和不重叠约束。为降低求解难度，本文采用基于排列的编码方式，将一个候选解表示为工件编号的排列序列：
           　　　　　π=(π_1,π_2,?"?",π_n)           (4-25)　　其中，π_k表示第k个被放置的工件编号，n表示待排样工件的数量。排列序列中的先后顺序决定了工件的放置优先级，排在前面的工件优先进入板材进行放置，排在后面的工件则在剩余空间中继续寻找可行位置。
　　例如，若某一候选解表示为：
           　　　　　π=(3,1,4,2,5)           (4-26)　　则表示系统会按照第3个、第1个、第4个、第2个、第5个工件的顺序依次进行放置。由于不同的放置顺序会影响板材剩余空间的形态，因此即使输入的板件集合完全相同，不同排列也可能得到不同的板材利用率。
　　采用排列编码的优点在于：它将原本复杂的坐标搜索问题转化为排列顺序优化问题，降低了直接求解二维坐标位置的难度。同时，排列编码结构简单，便于通过交换、插入等操作生成邻域解，适合与禁忌搜索等元启发式算法结合使用。
4.3.2 启发式编码方案
　　排列编码只能表示工件的放置顺序，不能直接得到工件在板材中的具体坐标。因此，需要设计解码算法，将排列序列转换为实际可用的排样结果。本文采用天际线放置算法作为启发式解码器。
　　给定一个排列序列π后，解码器按照排列顺序依次取出工件，并在当前板材的可用空间中寻找合适位置进行放置。天际线算法通过维护已占用区域的顶部轮廓来描述当前板材的剩余可放置空间。每放置一个工件后，系统都会更新天际线结构，使其反映新的空间占用情况。对于当前待放置工件，算法会在天际线中寻找满足边界约束和不重叠约束的位置，并优先选择高度较低、位置较靠左的放置点，从而尽可能减少空间碎片。
　　解码过程完成后，系统可以得到当前排列对应的排样结果，包括每个成功放置工件的坐标、实际放置尺寸、是否旋转以及当前板材利用率。板材利用率作为该排列方案的评价指标，其计算方式为：
           　　　　　fitness(π)=rate=(∑_(i∈P)?s_i )/S           (4-27)　　其中，P表示当前板材中成功放置的工件集合，s_i表示第i个工件的面积，S表示单张板材面积。利用率越高，说明该排列经过解码后得到的排样效果越好。
　　需要注意的是，天际线算法本身是一种启发式放置方法，它并不保证每一次放置都达到全局最优，但具有计算速度较快、实现结构清晰、适合矩形排样场景等优点。因此，本文将天际线算法作为解码器，用于快速评价不同排列序列的排样效果。
4.3.3 元启发式搜索策略
　　仅使用天际线算法按照固定顺序进行放置时，排样结果容易受到初始工件顺序的影响。为了进一步提高板材利用率，本文在排列编码的基础上引入禁忌搜索算法，对工件排列顺序进行优化。
　　禁忌搜索首先生成一个初始排列，并通过天际线算法计算该排列对应的板材利用率。随后，算法在当前排列的基础上生成若干邻域解，例如随机交换排列中若干工件的位置，得到新的工件放置顺序。对于每一个邻域排列，系统调用天际线解码器生成排样结果，并计算其适应度值。若某一邻域解的适应度优于当前解，则将其作为新的搜索方向。
　　为了避免搜索过程反复访问已经搜索过的排列，禁忌搜索通过禁忌表记录近期或已访问过的排列路径。当新生成的排列已经存在于禁忌表中时，系统通常会跳过该解，从而减少重复搜索并降低陷入局部最优的可能性。若某个被禁忌的解优于当前历史最优解，则可以通过特赦准则接受该解，以避免错过更优方案。
4.4 天际线放置算法设计
　　天际线算法是一种常用于二维矩形排样问题的启发式放置算法。其核心思想是通过维护板材中已放置区域的顶部轮廓，动态描述当前板材的剩余可用空间。在排样过程中，算法按照给定的工件排列顺序依次放置板件，并在当前天际线结构中寻找满足约束条件的可行位置。每成功放置一个板件后，系统更新天际线轮廓，使其能够反映新的空间占用情况。
　　与直接在整个板材平面中搜索可行坐标相比，天际线算法只需要关注由已放置板件形成的顶部轮廓位置，能够有效减少候选坐标数量，提高放置效率。同时，该算法采用“最低最左”的贪心策略，优先将板件放置在高度较低且位置靠左的区域，有利于减少空间碎片，提高板材利用率。
4.4.1 天际线数据结构
　　在天际线算法中，板材内部已放置区域的顶部轮廓由若干条水平线段组成。每一条天际线线段可以表示为：
　　　　　　　　　　seg=(x,y,width)           (4-28)　　其中，x表示该线段的起始横坐标，y表示该线段当前高度，width表示该线段在水平方向上的宽度。
　　在算法初始化时，板材内部尚未放置任何板件，因此天际线只有一条初始线段，其起点位于板材左下角预留间隙之后，高度为预留间隙，宽度为板材可用宽度，即：
           　　　　　seg_0=(gap,gap,L-2gap)           (4-29)　　其中，L表示板材长度，gap表示板件与板材边界之间的最小间隙。该初始线段表示板材底部从gap到L-gap的区域均可用于放置板件。
　　随着板件不断被放置，天际线集合会不断发生变化。设当前天际线集合为：
           　　　　　Skyline={seg_1,seg_2,?"?",seg_q}           (4-30)　　其中，q表示当前天际线线段数量。各线段按照起始横坐标从小到大排列，并共同描述当前板材内部可用空间的顶部轮廓。
4.4.2 工件放置策略
　　对于排列序列中的当前待放置板件，算法首先获取其原始长度和宽度。若系统允许板件旋转，则该板件存在两种候选放置方式：原始方向和旋转90^?后的方向；若系统不允许旋转，则只保留原始方向作为候选方案。
　　设当前候选放置尺寸为：
           　　　　　(p_w?,p_h )           (4-31)　　其中，p_w表示当前候选方向下板件的实际宽度，p_h表示当前候选方向下板件的实际高度。
　　对于天际线集合中的任意一条线段seg=(x,y,width)，若要将当前板件放置在线段起点处，则需要满足以下条件：
           　　　　　width≥p_w           (4-32)           　　　　　x+p_w+gap≤L           (4-33)           　　　　　y+p_h+gap≤B           (4-34)　　其中，式(4-32)表示当前天际线线段在水平方向上能够容纳该板件；式(4-33)表示板件放置后不会超出板材右边界；式(4-34)表示板件放置后不会超出板材上边界。
　　在实际放置过程中，若单条天际线线段宽度不足以容纳当前板件，算法还可以检查相邻线段合并后是否能够提供足够的水平空间。对于所有满足约束条件的候选位置，算法按照“最低最左”原则选择最优放置点，即优先选择y值最小的位置；当多个候选位置高度相同时，选择x值最小的位置。
　　该选择规则可以表示为：
           　　　　　(x^*,y^*)=arg?min?(y,x)           (4-35)　　其中，(x^*?,y^* )表示最终选定的放置坐标。通过该规则，算法能够优先利用板材底部和靠左区域，使剩余空间保持相对规整。
　　当允许旋转时，算法会同时评估原始方向和旋转方向下的候选位置。如果旋转后的尺寸能够获得更低或更靠左的可行位置，则选择旋转方向进行放置；否则保持原始方向。这样可以在不额外增加复杂控制逻辑的情况下，使旋转选择自然参与排样优化过程。
4.4.3 天际线更新策略
　　当板件成功放置后，原有天际线结构需要进行更新，以反映该板件对板材空间的占用情况。设当前板件的放置坐标为(x_i?,y_i )，实际放置宽度为W_i，实际放置高度为H_i，则该板件占用的水平范围为：
           　　　　　[x_i,x_i+W_i ]           (4-36)　　放置完成后，在板件上方会形成一条新的天际线线段，该线段可以表示为：
           　　　　　seg_new=(x_i,y_i+H_i+gap,W_i)           (4-37)　　其中，y_i+H_i+gap表示板件上方预留间隙后的新高度。
　　更新天际线时，算法需要对被当前板件覆盖的旧线段进行处理。对于与板件水平范围发生重叠的线段，需要根据覆盖情况进行分割。板件左侧未被覆盖的部分保留原高度，板件右侧未被覆盖的部分同样保留原高度，而板件正上方区域则由新线段代替。完成分割和新增后，系统对所有天际线线段按照起始横坐标进行排序，并合并相邻且高度相同的连续线段，以减少线段数量，保持天际线结构简洁。
　　通过上述更新过程，天际线结构能够始终准确描述当前板材的可放置轮廓，为后续板件放置提供依据。
4.5 禁忌搜索优化策略
　　天际线算法能够根据给定的板件排列顺序快速生成排样方案，但其结果容易受到初始排列顺序的影响。若较大的板件或形状特殊的板件放置顺序不合理，可能导致后续板件难以放入，从而降低板材利用率。为进一步优化板件放置顺序，本文在天际线解码算法的基础上引入禁忌搜索算法。
　　禁忌搜索是一种元启发式搜索算法，它通过在当前解的邻域中不断寻找更优解，并使用禁忌表记录已经访问过的解或移动路径，从而避免搜索过程陷入局部最优或产生循环。在本系统中，禁忌搜索的优化对象不是板件的具体坐标，而是板件的排列顺序。每一个排列序列经过天际线算法解码后，都可以得到一个对应的排样方案和板材利用率。禁忌搜索通过不断调整排列顺序，使系统逐步接近较优的排样方案。
4.5.1 初始解构造
　　禁忌搜索首先需要构造一个初始解。本文将待排样板件集合随机打乱，形成初始排列序列：
           　　　　　π_0=(π_1,π_2,?"?",π_n)           (4-38)　　其中，π_0表示初始排列，π_k表示第k个被放置的板件编号。
　　得到初始排列后，系统调用天际线解码算法对其进行排样，获得对应的板件坐标、旋转状态和板材利用率。初始排列的利用率作为初始适应度值，记为：
           　　　　　fitness(π_0)=rate(π_0)           (4-9)　　搜索开始时，将该初始解同时作为当前解和历史最优解。随后，算法在当前解的基础上生成邻域解，并通过迭代方式不断改进排样结果。
4.5.2 领域解生成
　　邻域解是指由当前解经过一定扰动后得到的新解。在排列编码方式下，邻域解可以通过交换排列中两个或多个板件的位置生成。本文采用随机交换方式构造邻域解，即从当前排列中随机选择两个不同位置，并交换这两个位置上的板件编号。
　　为增强搜索扰动能力，系统在生成一个邻域解时连续执行多次随机交换。设当前排列为π，经过若干次交换后得到的新排列为：
           　　　　　π^'=swap(π)           (4-40)　　其中，π^'表示由当前排列生成的邻域排列。本文中，每个邻域解通过连续交换6对位置生成。该方式能够在保持与当前解一定相似性的同时，产生足够的变化，避免搜索步长过小导致算法停留在局部区域。
　　每一轮迭代中，系统会生成多个邻域候选解，并分别调用天际线算法进行解码和评价。设每一代生成的邻域候选解数量为N，则当前解π的邻域集合可以表示为：
           　　　　　Neighbor(π)={π_1^',π_2^',?"?",π_N^'}           (4-41)　　在本文算法设置中，每一代生成N=500个邻域候选解，以保证搜索具有一定的广度。
4.5.3 禁忌表设计
　　在禁忌搜索过程中，如果算法反复访问已经搜索过的排列，会造成计算资源浪费，并可能导致搜索在局部区域内循环。为解决这一问题，本文使用禁忌表记录已访问过的排列序列。
　　由于排列序列本身较长，若直接将完整序列作为字符串存储，可能带来较大的存储和比较开销。本文采用树形结构存储已访问排列。树的路径表示一个完整的排列序列，根节点对应排列中的第一个板件编号，子节点按排列顺序依次展开。当需要判断某一排列是否已经访问过时，系统从根节点开始逐层匹配，若能够沿树路径完整匹配到叶节点，则说明该排列已存在于禁忌表中；若匹配过程中出现缺失节点，则说明该排列尚未访问，可以加入禁忌表并参与评价。
　　为了提高查询效率，禁忌表外层使用哈希映射结构，以排列中的第一个板件编号作为键，将具有相同首个板件的排列归入同一棵树中。该设计能够减少不必要的比较范围，提高禁忌判断效率。
4.5.4 适应度评价与最优解更新
　　对于每一个不在禁忌表中的邻域排列，系统都会调用天际线算法进行解码，并计算对应的板材利用率。该利用率即为该排列的适应度值：
           　　　　　fitness(π^')=(∑_(i∈P)?s_i )/S           (4-42)　　其中，P表示当前排列经过天际线解码后成功放置到板材中的板件集合，s_i表示板件面积，S表示单张板材面积。
　　在每一代搜索过程中，系统从全部可接受的邻域解中选出适应度最高的解作为本代局部最优解。若本代局部最优解的适应度高于历史全局最优解，则更新全局最优解。其更新规则可表示为：
           　　　　　best={■(π^',&fitness(π^')>fitness(best)@best,&fitness(π^')≤fitness(best))┤           (4-43)　　其中，best表示当前历史最优排列。
　　通过不断更新局部最优解和全局最优解，禁忌搜索可以在有限迭代次数内逐步寻找更优的板件放置顺序。
4.5.5 特赦准则与终止条件
　　禁忌表虽然能够避免重复搜索，但也可能阻止某些具有潜在价值的候选解被再次访问。为避免错失更优解，本文引入特赦准则。当某个候选排列虽然已存在于禁忌表中，但其适应度高于当前历史最优解时，系统仍然接受该解，并用其更新全局最优解。特赦准则可以表示为：
           　　　　　fitness(π^')>fitness(best)           (4-44)　　若式(4-46)成立，则即使该候选解属于禁忌解，也允许其参与最优解更新。该机制可以在保持禁忌搜索避免循环能力的同时，提高算法发现更优解的可能性。
　　本文设置最大迭代代数为：
           　　　　　MAX_GEN=300           (4-45)　　每一代生成邻域候选解数量为：
           　　　　　N=500           (4-46)　　当算法达到最大迭代代数后，搜索终止，并输出历史最优排列及其对应的排样方案。
4.6 多板材排样策略
　　在实际生产订单中，待切割板件数量通常较多，单张标准板材往往无法容纳全部板件。因此，仅对单张板材进行排样不能满足完整订单的生产需求。为解决多张板材排样问题，本文采用多板材迭代排样策略。该策略以单板材排样算法为基础，每次对当前剩余板件集合进行排样，将已成功放置的板件从剩余集合中移除，再对未放置板件继续启用新的板材进行排样，直至所有板件完成排布。
　　多板材排样策略能够将复杂的多容器问题拆解为多个单容器排样问题，既降低了求解复杂度，又便于系统保存和展示每张板材的排样结果。
4.6.1 多容器迭代排样
　　设订单中全部待排样板件集合为：
           　　　　　R_0={1,2,?"?",n}           (4-47)　　其中，R_0表示初始剩余板件集合。系统首先以R_0为输入，调用禁忌搜索和天际线算法求解第一张板材的排样方案。设第k张板材中成功放置的板件集合为P_k，则当前轮排样结束后，剩余板件集合更新为：
           　　　　　R_k=R_(k-1)-P_k           (4-48)　　若R_k为空，说明全部板件已经完成排样，算法结束；若R_k不为空，则系统继续启用下一张相同规格的板材，对剩余板件进行排样。
4.6.2 剩余工件处理
　　在多板材排样过程中，准确维护剩余板件集合是保证算法正确性的关键。每当某一张板材完成排样后，系统需要根据当前排样结果识别已经成功放置的板件，并将其从剩余板件集合中移除。
　　若每个板件具有唯一编号，则可以直接根据板件编号进行移除。若输入数据中存在尺寸、材质和数量完全相同的多个板件，则需要结合板件编号或实例化后的工件对象进行处理，避免误删未放置的同类板件。
　　剩余板件处理需要满足以下要求：
　　第一，已成功放置的板件必须从剩余集合中移除，避免后续板材重复排样。
　　第二，未成功放置的板件必须保留在剩余集合中，继续参与下一张板材的排样。
　　第三，对于尺寸相同但数量不同的板件，应按照实例对象逐一移除，确保订单板件数量准确。
　　第四，若某一轮排样没有任何板件被成功放置，需要触发异常处理或兜底机制，避免算法陷入死循环。
　　通过上述处理方式，可以保证多板材排样过程中各板件只会被放置一次，且最终所有可放置板件均能够被分配到对应板材中。
4.6.3 单件兜底机制
　　由于禁忌搜索依赖邻域交换和迭代改进，当剩余板件数量较少或剩余板件尺寸较特殊时，可能出现当前搜索未能成功放置任何板件的情况。若此时直接终止算法，可能会导致实际上能够放入板材的板件未被处理。因此，本文设计单件兜底机制，提高多板材排样过程的稳定性。
　　当某一轮单板材排样结束后，若成功放置板件集合为空，即：
           　　　　　P_k=?           (4-49)　　系统将逐一尝试把剩余板件单独放入一张新板材中。对于每一个剩余板件，分别判断其原始方向或旋转方向是否满足板材边界约束。若某个板件可以单独放入板材，则将其作为当前板材的排样结果，并从剩余集合中移除。若有多个板件均可单独放入，则可以优先选择面积较大的板件，以提高当前板材利用率。
　　若所有剩余板件均无法单独放入板材，则说明存在板件尺寸超出板材可容纳范围的情况。此时系统应终止排样过程，并提示异常信息，提醒用户检查板件尺寸、板材规格或旋转参数设置。
4.7 本章小结
　　本章围绕柜门板材切割排样问题展开建模与算法设计。首先，将实际柜门板材切割场景抽象为二维矩形装箱问题，并建立了包含符号定义、决策变量、约束条件和目标函数的数学模型。在此基础上，本文设计了“排列编码+天际线解码+禁忌搜索优化”的总体求解框架，将复杂的二维坐标排布问题转化为板件排列顺序优化问题。
　　随后，本章对天际线放置算法进行了详细设计。该算法通过维护板材已占用区域的顶部轮廓，按照最低最左原则为板件寻找可行位置，并在每次放置后动态更新天际线结构，从而实现对矩形板件的快速排样。在搜索优化方面，本文采用禁忌搜索算法对板件排列顺序进行迭代优化，通过邻域解生成、禁忌表记录、适应度评价和特赦准则等机制，提高算法跳出局部最优的能力。
　　最后，针对实际订单中单张板材无法容纳全部板件的情况，本章设计了多板材迭代排样策略。该策略通过维护剩余板件集合，逐张板材进行排样，并结合单件兜底机制处理搜索停滞或异常板件情况。通过上述建模与算法设计，系统能够在满足边界约束、不重叠约束和旋转约束的基础上，生成具有较高板材利用率的切割排样方案，为后续系统实现和排样结果可视化提供了理论和算法基础。

5.2 后端功能实现
　　后端功能采用Controller、Service和Mapper分层实现。Controller负责接收请求和组织响应，Service负责业务处理，Mapper负责数据访问。系统业务接口默认返回Result结构，包含code、msg和data三个字段，便于前端统一处理。需要特别说明的是，历史同步算法接口POST/algorithm/answer按项目既有约定直接返回List<SolutionResponseDTO>，这一点与其他业务接口不同，前端在algorithm.js中单独处理。
5.2.1 用户登录与身份认证实现
　　用户登录入口由AuthController提供。前端登录表单提交用户名和密码后，请求/auth/login接口。后端根据用户名查询用户信息，校验账号状态和密码，验证通过后生成JWT Token并返回给前端。前端保存Token后，后续访问客户、板材、订单、排样结果和生产任务等接口时，在请求头中携带Authorization信息。
　　业务接口鉴权由TokenInterceptor统一完成。请求进入后端时，拦截器读取Bearer Token并校验有效性，通过后将用户编号写入UserContext。后续Service层可以通过UserContext获取当前用户，从而保证查询和写入操作限定在当前用户范围内。请求结束后，拦截器清理线程上下文，避免用户信息残留。
　　该实现把认证逻辑从业务接口中抽离出来，使Controller只关注参数接收和结果返回。用户是否登录、Token是否有效和当前用户编号都由拦截器统一处理。

5.3 排样算法模块实现
　　第五章算法部分重点说明代码如何协作完成排样，而不是重复禁忌搜索和天际线算法原理。系统中排样模块主要由ReadDataUtil、TabuSearch、TabuMapTree以及Instance、Square、Solution、PlaceSquare等模型类组成。ReadDataUtil负责组织完整求解流程，TabuSearch负责单张板材的搜索与放置评价，TabuMapTree负责记录已搜索排列，模型类负责承载输入和输出数据。
5.3.1 ReadDataUtil的流程组织实现
　　ReadDataUtil是接口层和算法层之间的衔接类。Controller接收到InstanceDTO后，最终进入ReadDataUtil.getSolution方法。该方法读取容器尺寸、切割间隙、旋转开关和矩形列表，将DTO数据转换为算法内部使用的Instance和Square集合，然后启动多容器求解流程。
　　在多容器求解中，ReadDataUtil维护一个剩余板件列表。每轮循环使用当前剩余板件构造新的Instance，并创建TabuSearch对象求解当前板材。TabuSearch返回Solution后，ReadDataUtil提取已经放置的板件，将它们从剩余列表中移除，再把当前板材结果封装为SolutionResponseDTO。只要还有剩余板件，方法就继续创建下一张板材进行求解。
　　如果某一轮没有板件被成功放置，ReadDataUtil会执行兜底处理，尝试逐个检查剩余板件是否可以单独放入容器。只要存在可放入板件，流程就继续推进；如果所有剩余板件都无法放入，则说明输入中存在尺寸超出容器能力的板件，系统结束求解并返回已有结果或错误信息。
5.3.2 TabuSearch的单板求解实现
　　TabuSearch承担单张板材内部的求解工作。创建对象时，它接收Instance中的容器尺寸、间隙、旋转开关和板件列表。search方法负责搜索较优板件排列，evaluate方法负责对某个排列进行放置评价。两者配合后，TabuSearch输出当前板材中利用率较高的Solution。
　　search方法首先生成初始排列并调用evaluate计算初始方案。随后进入迭代过程，每一代从当前排列出发，通过交换板件位置生成多个候选排列。候选排列如果没有被TabuMapTree记录过，就进入evaluate进行评价。评价结果优于当前局部最优解时更新局部最优，优于历史全局最优解时更新全局最优。迭代结束后，方法返回历史最优Solution。
　　evaluate方法负责把候选排列真正转化为放置结果。该方法按排列顺序处理板件，维护当前板材的空间轮廓和已放置板件集合。每处理一个板件，方法先尝试原方向；如果rotateEnable为true，再尝试旋转后的方向。找到可行位置后，系统记录PlaceSquare信息，包括板件编号、坐标、实际尺寸和旋转状态，并更新空间轮廓。排列处理完成后，方法根据已放置面积计算利用率并生成Solution。
5.3.3 TabuMapTree的禁忌记录实现
　　TabuMapTree用于保存已经搜索过的板件排列，避免TabuSearch反复评价相同顺序。系统使用树形结构按板件顺序逐层记录排列，外层以排列首个板件为入口，后续节点依次表示排列中的下一个板件。
　　当TabuSearch生成候选排列时，会先调用TabuMapTree判断该排列是否已经存在。如果不存在，说明这是新的候选解，系统将其加入禁忌结构并继续执行evaluate；如果已经存在，则跳过该候选解。由于evaluate会进行位置判断和轮廓更新，减少重复评价能够降低计算消耗。
　　TabuMapTree与TabuSearch的职责划分比较清晰。TabuSearch负责生成候选解、调用评价方法和更新最优解，TabuMapTree只负责记录和查询访问状态。这种实现方式使禁忌逻辑不会混入具体放置代码，也便于后续调整搜索策略。
5.3.4 法结果封装实现
　　算法内部的Solution和PlaceSquare偏向计算过程，前端需要的是可以直接渲染的响应结构。因此ReadDataUtil在每轮求解后，会把Solution转换为SolutionResponseDTO，包含容器编号、利用率、板件坐标、板件尺寸和旋转状态等字段。
　　对于多板材结果，ReadDataUtil会生成多个SolutionResponseDTO并组成列表返回。前端根据列表长度判断使用了多少张板材，根据每个对象中的坐标绘制对应容器。该封装过程隔离了算法内部模型和接口模型，使前端无需了解TabuSearch内部细节，只需处理稳定的响应字段。
5.4 前端页面实现
　　前端实现重点是把后端接口和算法结果转化为可操作页面。网页端通过路由划分登录、工作台、客户管理、板材管理、加工数据输入、排版工作台和生产看板等页面。接口请求集中封装在api目录中，认证状态由auth store维护，排样相关交互由useCuttingTable、useAlgorithmSubmit和useLayoutCanvas等组合式函数承担。
5.4.1 登录与基础资料页面实现
　　登录页面由LoginView实现。用户输入账号和密码后，页面调用登录接口，成功后保存Token并跳转到系统工作台。路由守卫会检查访问页面是否需要登录，未登录时跳转到登录页。Axios请求封装在发送请求前自动附加Token，在响应异常时统一提示错误信息。
　　客户页面和板材页面均采用查询区、表格区、分页区和表单弹窗的结构。客户页面围绕客户名称、电话、地址和启用状态进行维护；板材页面围绕品牌、材质、颜色、尺寸和厚度进行维护。两个页面都支持新增、编辑、删除和批量操作，接口成功后刷新列表并显示反馈信息。
5.4.2 加工数据输入页面实现
　　加工数据输入页是排样前的数据准备页面。页面顶部展示订单信息，左侧提供原料板和余料选择，右侧提供可编辑下料表格。用户可以在表格中录入板件名称、长度、宽度、数量、材质、颜色和封边要求。表格支持键盘导航和TSV粘贴，便于从Excel中复制多行加工数据。
　　页面底部汇总栏会根据当前表格内容计算板件数量和面积信息。用户确认排版时，前端将选中的板材尺寸、旋转设置、切割间隙和板件列表组装为算法接口参数，并传递给排版工作台。该页面把订单业务数据转换为算法输入数据，是系统实现业务流程闭环的关键环节。
5.4.3 排版工作台页面实现
　　排版工作台由LayoutWorkbenchView和多个切割业务组件组成。顶部工具栏提供排版、参数、缩放、导出、保存和返回等操作；左侧历史面板显示当前订单的历史排样记录；中间Canvas区域用于展示排样图形；摘要区域展示利用率、容器数量和板件统计信息。
　　用户点击排版后，useAlgorithmSubmit负责调用算法接口并处理返回结果。如果返回的是同步结果，页面直接渲染；如果使用异步任务，页面根据taskId查询任务状态，完成后读取resultJson。加载历史记录时，页面通过排样结果接口获取保存过的结果，并重新恢复到画布中。
　　Canvas绘制由useLayoutCanvas负责。该函数根据板材尺寸和画布尺寸计算缩放比例，绘制板材边界和板件矩形，并支持缩放、平移和鼠标悬停提示。每个板件按照算法返回的坐标、尺寸和旋转状态绘制，用户可以直观看到板件在板材上的位置。当结果包含多张板材时，页面显示板材切换标签。

5.5 本章小结
　　本章从系统已经实现的功能出发，说明了柜门板材切割排版系统在后端接口、排样算法和前端页面上的落地情况。后端完成了登录鉴权、客户管理、板材管理、订单与加工数据、排样结果和生产任务等功能接口，并明确区分了普通业务接口Result返回结构和同步算法接口List<SolutionResponseDTO>返回结构。
　　算法模块通过ReadDataUtil、TabuSearch和TabuMapTree之间的协作完成实际求解。ReadDataUtil负责输入转换、多容器循环和结果封装，TabuSearch负责单板搜索和放置评价，TabuMapTree负责记录已访问排列并减少重复搜索。三个部分共同支撑系统从板件列表到排样坐标结果的转换。
　　前端实现了登录、基础资料维护、加工数据输入、排版工作台和生产看板等页面，并通过Canvas展示排样方案。经过上述实现，系统已经能够完成从业务数据录入到算法求解、从结果可视化到生产任务跟踪的核心流程，满足柜门板材切割排版系统的主要使用需求。

6.3 本章小结
　　本章主要对系统的接口功能和前端展示效果进行了测试。测试内容围绕系统实际使用流程展开，包括用户登录、客户资料维护、板材规格维护、排样参数提交和排样结果返回等场景。登录接口测试中，分别验证了正确账号登录、错误密码登录和空参数提交等情况，用于检查系统能否正确返回 token 或失败提示。客户管理和板材管理接口测试中，重点检查新增、查询、修改和删除等基础维护操作是否能够正常完成。
　　在排样相关测试中，系统主要验证了板材尺寸、板件尺寸、旋转设置和切割间隙等参数能否正常提交到后端，后端能否调用算法模块返回利用率、板材数量和板件坐标等数据。前端页面测试则通过 Chrome 浏览器进行，重点观察接口返回结果能否在表格中展示，并能否通过 Canvas 绘制出对应的排样图。
　　从测试结果看，系统主要接口能够按照预期返回数据，登录鉴权、基础资料维护和排样计算流程可以正常执行。对于部分异常输入，系统能够返回相应提示，避免继续生成无效排样结果。但测试过程中也可以看出，当前测试数据规模仍然有限，主要集中在常规板件数量和基础异常场景上。后续如果系统继续完善，还需要增加更大规模订单、多种板材规格、极端尺寸工件和余料复用等测试场景，以进一步验证系统在复杂加工任务中的稳定性。

7 结论
　　本文围绕柜门板材切割排版业务展开研究，针对人工排版过程中存在的数据分散、重复录入、排样效率较低和结果不便追溯等问题，设计并实现了一套基于 Spring Boot 的柜门板材切割排版系统。系统以柜门板材加工流程为基础，将客户资料、板材规格、订单板件、排样参数、算法结果和生产任务等内容纳入统一管理，使排样计算不再只是单独的算法操作，而是能够与业务数据录入和结果保存形成连续流程。
　　在系统功能实现方面，后端采用 Spring Boot、MyBatis-Plus 和 MySQL 完成接口开发与数据存储，主要实现了用户登录、客户管理、板材管理、订单管理、排样结果保存和生产任务管理等功能。前端采用 Vue 3、Element Plus 和 Canvas 2D 完成页面交互与图形展示，用户可以在网页端完成板材选择、板件尺寸录入、参数设置和排样结果查看。通过前后端接口交互，系统能够将用户录入的加工数据转换为算法输入，并将算法输出的板材利用率、板件坐标和旋转状态返回给前端进行展示。
　　在排样算法方面，本文采用禁忌搜索与天际线放置算法相结合的方式进行求解。禁忌搜索用于调整板件的排列顺序，避免算法在较短时间内反复搜索相似方案；天际线放置算法用于根据当前排列顺序计算具体坐标，并在放置过程中检查边界、间隙、旋转和重叠约束。当单张板材无法完成全部排样时，系统会将已放置板件移除，并对剩余板件继续进行多容器排样。该方案虽然不能保证得到全局最优解，但实现过程较清晰，计算结果也便于转换为前端 Canvas 图形，适合本系统的工程实现需求。
　　在系统测试方面，本文使用 ApiFox 对登录认证、客户管理、板材管理、排样参数提交和排样结果返回等接口进行了测试，并通过 Chrome 浏览器检查前端页面展示和交互效果。测试结果表明，系统能够完成主要业务流程，接口返回结构较统一，排样结果能够以表格和图形方式展示。对于错误密码、空参数和部分异常排样输入，系统也能够返回相应提示，避免前端继续展示无效结果。
　　由于开发周期和测试条件有限，系统仍存在一些不足。首先，当前排样算法主要针对规则矩形板件，对异形板件、纹理方向强约束和复杂余料优先策略支持还不够充分。其次，测试数据规模相对有限，对大批量订单、多种板材混合使用和高并发访问等情况验证不足。再次，系统在生产任务流转、排样结果导出和历史方案对比方面仍有进一步完善空间。后续研究可以从算法优化、余料复用、导出功能和生产流程管理等方面继续改进，使系统更接近实际柜门加工场景中的长期使用需求。
