# user-manual/ 工作规则

## 目录文件

- `需求文档.md`：需求池（Bug / 新功能 / 优化），含”用户自由记录区”
- `需求文档-已完成.md`：已归档完成项
- `操作手册.md`：用户操作指南

## 需求文档维护

- 用户在”用户自由记录区”随手记录，AI 负责归类到下方结构化表格。
- 编号：`B-XXX`（Bug）、`F-XXX`（新功能）、`O-XXX`（优化），接续 `需求文档-已完成.md` 最后编号。
- 已完成项移入 `需求文档-已完成.md`。

## 整理自由记录区

- 允许润色、拆句、归类，但**保留全部细节**：场景、触发条件、操作路径、异常表现、期望效果、限制条件、关键名词和数量。
- 一条记录含多个独立诉求时拆成多条，不合并。
- 用户表述不清时保留不确定点，备注列标注”待确认”，不擅自补成确定结论。

## 备注编写

- 写清涉及端和入口：网页端 `frontend/`、小程序端 `miniprogram/`、后端 `src/main/java/.../controller/`、数据库脚本 `src/main/resources/db/migration/`。
- 能定位到页面/组件/API/文件时写出具体路径；不确定时写建议检查范围，不编造不存在的文件。
- Bug 类：现象、可能根因、排查文件、验证建议。功能类：实现要点、受影响接口/状态、建议复用组件。
- 短、准、可执行，不替代详细设计文档。

## 格式规范

- 状态统一用语：待确认 / 待验收 / 待规划 / 已记录
