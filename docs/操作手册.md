## 1. 系统概述

柜门板材切割排版系统是一个面向家具制造业的切割优化与生产管理平台。核心能力包括：

- **切割优化引擎**: 禁忌搜索 + 遗传算法双算法策略模式，支持多容器迭代填充、板材旋转、间隙控制
- **订单生命周期管理**: 10 状态状态机，从待审核到已交付全流程追踪
- **CRUD 业务管理**: 客户、板材、订单、订单明细、余料、排样结果
- **RBAC 权限体系**: admin/operator/viewer 三角色 9 权限码，接口级 + 按钮级鉴权
- **操作审计**: 覆盖 8 个控制器 20 个写操作的 AOP 审计日志
- **Excel 导入导出**: EasyExcel 批量导入导出 + 模板下载
- **Docker 一键部署**: MySQL + Nginx + Backend 三容器编排

**适用角色**:

| 角色 | 权限范围 |
|------|---------|
| 管理员 (admin) | 全部功能：用户管理、角色分配、审计日志、所有业务 CRUD、算法执行 |
| 操作员 (operator) | 业务操作：客户/板材/订单/余料/排样 CRUD、算法执行 |
| 查看者 (viewer) | 只读：所有模块分页查询 + 算法执行 |

**访问入口**:

| 端 | 地址 | 用途 |
|----|------|------|
| 网页端 | `http://127.0.0.1:5173` (开发) / `http://127.0.0.1:80` (Docker) | 后台管理、排样可视化 |
| 微信小程序 | 微信开发者工具导入 `miniprogram/` | 现场录入、客户板材管理 |

## 3. 安装与部署

### 3.1 源码获取

```bash
git clone <仓库地址>
cd cutting-system
```

### 3.2 本地开发环境

#### 3.2.1 数据库初始化

确保本地 MySQL 8.0 运行中，创建数据库：

```sql
CREATE DATABASE IF NOT EXISTS board_cutting_db DEFAULT CHARSET utf8mb4;
```

首次运行时 MyBatis-Plus 自动建表，也可手动执行迁移脚本：

```sql
source src/main/resources/db/migration/20260430_align_bishe_schema.sql;
source src/main/resources/db/migration/20260507_rbac.sql;
source src/main/resources/db/migration/20260507_audit_log.sql;
source src/main/resources/db/migration/20260507_order_status.sql;
source src/main/resources/db/migration/20260507_algorithm_task.sql;
```

#### 3.2.2 配置文件

复制并编辑 `src/main/resources/application.yml`，修改数据库连接信息：

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/board_cutting_db?useUnicode=true&characterEncoding=utf8mb4
    username: root
    password: your_password
```

JWT 密钥配置（需设置为环境变量，避免硬编码）：

```yaml
jwt:
  secret: ${JWT_SECRET:default-dev-key-change-in-production}
  expiration: 86400000
```

#### 3.2.3 启动服务

**一键启动（推荐）**:

```powershell
powershell.exe -ExecutionPolicy Bypass -File scripts\start-dev.ps1
```

脚本会自动检测端口占用、安装前端依赖（首次）、启动后端和前端，并等待两者就绪后输出访问地址。

常用参数：

| 参数 | 用途 |
|------|------|
| `-SkipInstall` | 跳过 `npm install`，加快后续启动 |
| `-Restart` | 先调用 `stop-dev.ps1` 停止已有服务再启动 |

**备用方案——直接启动**（当 PowerShell 脚本不可用时）:

Maven 本地仓库隔离可避免全局 `~/.m2` 缓存冲突，建议始终携带：

```bash
# 终端 1：启动后端
mvn "-Dmaven.repo.local=target/.m2" spring-boot:run

# 终端 2：启动前端
cd frontend
npm install    # 首次运行或依赖变更时
npm run dev
```

如果需要在单个终端中后台运行（如 Git Bash / WSL）：

```bash
# 后台启动后端，日志写入文件
nohup mvn "-Dmaven.repo.local=target/.m2" spring-boot:run > target/logs/backend.log 2>&1 &

# 后台启动前端
cd frontend && nohup npm run dev -- --host 127.0.0.1 --port 5173 > ../target/logs/frontend.log 2>&1 &
```

- 后端运行在 `http://127.0.0.1:8080`
- 前端运行在 `http://127.0.0.1:5173`，Vite 开发服务器自动代理 `/api` 到后端
- 一键脚本的日志输出到 `logs/dev/backend.log` 和 `logs/dev/frontend.log`
- 直接启动时日志输出到控制台（或 `target/logs/` 如果使用了 nohup 重定向）

**停止服务**:

```powershell
powershell.exe -ExecutionPolicy Bypass -File scripts\stop-dev.ps1
```

如果使用直接启动方式，在对应终端按 `Ctrl+C` 停止，或后台运行时查找进程终止：

```bash
# 查找并终止后端（Windows 下可用 taskkill）
taskkill //F //FI "WINDOWTITLE eq mvn*"
# 终止前端 Vite
taskkill //F //IM node.exe
```

## 4. 基本使用指南

### 4.1 登录

1. 打开网页端 `http://127.0.0.1:5173` 或 `http://127.0.0.1:80`
2. 输入用户名和密码，点击登录
3. 登录成功后会获得 JWT Token，前端自动存储并在后续请求中携带

### 4.2 工作台 (Dashboard)

登录后默认进入工作台，展示：
- 客户总数
- 板材总数
- 启用板材数
- 各模块快捷入口

### 4.3 客户管理

路径: `客户管理` → 客户列表

| 操作 | 说明 |
|------|------|
| 查询 | 分页列表，按客户名称模糊搜索 |
| 新增 | 填写客户名称、手机号、地址，点击保存 |
| 编辑 | 点击行内编辑按钮，修改后保存 |
| 删除 | 点击删除按钮，确认后删除 |
| 批量导入 | 点击"批量导入"，上传 Excel 文件 |
| 批量导出 | 点击"导出"按钮，下载 Excel 文件 |
| 模板下载 | 点击"下载模板"，获取标准导入格式 |

### 4.4 板材管理

路径: `板材管理` → 板材列表

| 操作 | 说明 |
|------|------|
| 查询 | 分页列表，按品牌/材质/颜色/尺寸类型筛选 |
| 新增 | 填写品牌、材质类型、颜色、尺寸类型、长宽厚度、备注 |
| 编辑/删除 | 同客户管理 |
| 批量导入/导出 | 同客户管理 |

板材字段说明：
- `brand`: 品牌
- `materialType`: 材质类型（如实木颗粒板、多层实木板）
- `color`: 颜色
- `sizeType`: 尺寸类型（常规/定制）
- `width/length/thickness`: 宽/长/厚 (mm)
- `isEnabled`: 是否启用（禁用后不参与排样匹配）

### 4.5 订单管理

路径: `订单管理` → 订单列表

#### 4.5.1 新建订单

1. 点击"新增订单"
2. 选择客户、填写工序名称
3. 添加订单明细：零件名称、编码、板材、尺寸、数量、封边选项、纹理方向、是否允许旋转
4. 保存订单（初始状态：待审核）

#### 4.5.2 订单状态流转

| 状态码 | 状态名 | 可转换到 |
|--------|--------|---------|
| 0 | 待审核 | 已审核(1)、已驳回(-1) |
| 1 | 已审核 | 排样中(2)、已取消(-2) |
| 2 | 排样中 | 已排样(3)、排样失败(-3) |
| 3 | 已排样 | 生产中(4)、重新排样→已审核(1) |
| 4 | 生产中 | 已完工(5) |
| 5 | 已完工 | 已交付(6) |
| 6 | 已交付 | (终态) |
| -1 | 已驳回 | 待审核(0)→重新提交 |
| -2 | 已取消 | (终态) |
| -3 | 排样失败 | 已审核(1)→重新排样 |

操作方式：在订单详情页点击"状态变更"，选择目标状态并填写备注。

### 4.6 排样求解

路径: `排样求解` → 算法输入

#### 4.6.1 单算法求解

1. 输入容器尺寸（长 L、宽 W）
2. 选择是否允许旋转、设置板件间距
3. 添加待排样矩形列表（id、长、宽）
4. 选择算法（禁忌搜索/遗传算法）
5. 点击"提交"执行求解
6. 结果展示：利用率、各容器放置坐标可视化

#### 4.6.2 算法对比

1. 输入排样数据（同上）
2. 点击"对比算法"
3. 系统同时运行禁忌搜索和遗传算法
4. 并排展示两种算法的利用率和排版结果

### 4.7 余料管理

路径: `余料管理` → 余料列表

用于管理切割过程中产生的剩余板材。字段包括：
- 来源板材、来源订单
- 余料尺寸（宽/长/厚）
- 品牌、材质、颜色
- 状态（可用/已用/废弃）

### 4.8 排样结果管理

路径: `排样结果` → 结果列表

存储每次排样求解的历史结果，支持按订单查询。记录内容：
- 利用率、总面积、容器数量
- 排样结果 JSON（包含每块矩形的放置坐标）
- 导出文件路径

### 4.9 用户管理（仅管理员）

路径: `系统管理` → 用户管理

| 操作 | 说明 |
|------|------|
| 用户列表 | 分页查看所有用户 |
| 状态管理 | 启用/禁用用户账号 |
| 角色分配 | 为用户分配 admin/operator/viewer 角色 |

### 4.10 审计日志（仅管理员）

路径: `系统管理` → 审计日志

- 分页查看所有操作记录
- 按模块、操作人、状态筛选
- 导出审计日志到 Excel

## 5. 系统架构概览

```
┌──────────────────────────────────────────┐
│           Nginx (端口 80)                  │
│     静态资源 + /api → 后端代理             │
└──────────────┬───────────────────────────┘
               │
┌──────────────▼───────────────────────────┐
│       Spring Boot 后端 (端口 8080)         │
│  ┌─────────────────────────────────────┐ │
│  │  Controller 层 (14 个控制器)         │ │
│  │  → TokenInterceptor (JWT 鉴权)      │ │
│  │  → @RequirePermission (RBAC)        │ │
│  │  → @AuditLog (AOP 审计)             │ │
│  ├─────────────────────────────────────┤ │
│  │  Service 层 (10 接口 + 10 实现)      │ │
│  │  → 多租户隔离 (user_id)             │ │
│  ├─────────────────────────────────────┤ │
│  │  Mapper 层 (MyBatis-Plus 14 接口)   │ │
│  └─────────────────────────────────────┘ │
└──────────────┬───────────────────────────┘
               │
┌──────────────▼───────────────────────────┐
│         MySQL 8.0 (端口 3306/3307)        │
│  board_cutting_db (17 张业务表)           │
└──────────────────────────────────────────┘
```

**核心算法流程**:

```
InstanceDTO → ReadDataUtil.getSolution()
  → AlgorithmRegistry.create(algorithmName)
    → CuttingAlgorithm.search()
      → TabuSearch 或 GeneticAlgorithm
        → Skyline Placement (天际线放置)
        → TabuMapTree (禁忌记忆去重)
      → Solution { rate, placeSquareList }
  → 多容器迭代（剩余矩形循环填充）
→ SolutionResponseDTO
```

| 算法 | `POST /algorithm/compare`、`GET /algorithm/algorithms` | algorithm:execute |
| 算法 | `POST /algorithm/answer` (遗留) | algorithm:execute |
| 用户管理 | `GET /users`、`GET /users/{id}`、`PUT /users/{id}/status` | user:manage |
| 用户管理 | `PUT /users/roles`、`GET /users/roles` | user:manage |
| 审计日志 | `GET /audit-logs`、`GET /audit-logs/export` | user:manage |

### 6.3 通用响应格式

```json
{
  "code": 200,
  "msg": "success",
  "data": { ... }
}
```

异常：`POST /algorithm/answer` 直接返回 `List<SolutionResponseDTO>`。

### 6.4 算法输入/输出格式

**输入 (InstanceDTO)**:

```json
{
  "L": 2440,
  "W": 1220,
  "rotateEnable": true,
  "gapDistance": 5,
  "squareList": [
    {"id": "A1", "l": 600, "w": 400},
    {"id": "A2", "l": 800, "w": 500}
  ]
}
```

**输出 (SolutionResponseDTO)**:

```json
{
  "containerLength": 2440,
  "containerWidth": 1220,
  "rate": 0.923,
  "squareList": [{"id": "A1", "l": 600, "w": 400}],
  "placeSquareList": [{"x": 0, "y": 0, "l": 600, "w": 400}]
}
```

## 9. 缺陷分析与修复建议

> 以下缺陷按严重程度排序：严重 (Critical) → 高 (High) → 中 (Medium)。
> 修复方案为建议方向，实施前需评估对现有业务的影响。

### 缺陷 1 (严重): MD5 密码哈希 — **已知且接受，不做修复**

- **位置**: `util/MD5Util.java` (全文件), `service/impl/TUserServiceImpl.java:33,56`
- **影响范围**: 所有用户的密码安全
- **问题**: 用户密码使用 MD5 哈希存储。MD5 已被证明不具备抗碰撞和抗原像能力，彩虹表可在秒级完成破解。
- **处理决定**: 当前系统处于毕设/内部使用阶段，无外部用户数据。MD5 足以满足演示和内部使用需求。如需对外开放，应引入 BCrypt 替代。

### 缺陷 2 (高): TabuMapTree.add() 数组越界

- **位置**: `model/TabuMapTree.java:42-55`
- **影响范围**: 核心算法 — 当剩余矩形列表只有一个元素时，`algorithm/answer` 接口返回 HTTP 500
- **问题**: `add()` 方法在 `nodeSquare == null` 且列表大小为 1 时，设置 `nodeSquare` 后将 `index` 从 0 递增到 1，然后执行 `squareList.get(1)` 导致 `IndexOutOfBoundsException`
- **复现条件**: 排样结果只剩一个未放置矩形
- **修复建议**:
  ```java
  index++;
  if (index >= squareList.size()) return;
  ```

### 缺陷 3 (高): 注册竞态条件

- **位置**: `service/impl/TUserServiceImpl.java:49-62`
- **影响范围**: 用户注册流程
- **问题**: `register()` 方法先 `selectCount` 再 `insert`，无事务隔离。并发注册同一用户名可绕过重复检查，导致数据库约束冲突或重复账号。
- **修复建议**:
  1. 方法添加 `@Transactional(isolation = Isolation.READ_COMMITTED)`
  2. 数据库层面为 `t_user.username` 添加 UNIQUE 约束
  3. 捕获 `DuplicateKeyException` 并返回友好错误

### 缺陷 4 (高): 无 CORS 配置

- **位置**: 所有 `*Config*.java` — 未找到 `addCorsMappings`
- **影响范围**: 全局 API 安全
- **问题**: 未显式配置 CORS 规则。在没有 Spring Security 的情况下，Spring Boot 的默认行为可能导致跨域请求不受限制。任何网站页面都可在用户已登录的情况下发起认证请求。
- **修复建议**:
  ```java
  // WebConfig.java
  @Override
  public void addCorsMappings(CorsRegistry registry) {
      registry.addMapping("/**")
              .allowedOrigins("http://localhost:5173", "https://yourdomain.com")
              .allowedMethods("GET","POST","PUT","DELETE")
              .allowCredentials(true);
  }
  ```

### 缺陷 5 (高): 算法任务执行缺事务

- **位置**: `service/impl/AlgorithmServiceImpl.java:69-97`
- **影响范围**: 算法任务队列
- **问题**: `doExecuteTask()` 执行多次 `updateById` 操作（状态 0→1→2/-1）但未加 `@Transactional`。若执行中被中断，任务卡在"运行中"（status=1）永久无法恢复。并发调用同一 `taskId` 存在数据覆盖风险。
- **修复建议**: 添加 `@Transactional(rollbackFor = Exception.class)`，考虑引入乐观锁（version 字段）。

### 缺陷 6 (高): 订单状态转换缺校验

- **位置**: `entitys/DTO/OrderStatusTransitionDTO.java`(全文件), `controller/OrderController.java:76`
- **影响范围**: 订单状态机
- **问题**: `OrderStatusTransitionDTO` 中 `targetStatus` 和 `remark` 无任何校验注解 (`@NotNull`/`@Min`/`@Max`/`@Size`)，控制器也未使用 `@Valid`。传入 `null` 会导致 NPE，传入 `99` 会触发 `IllegalArgumentException`。
- **修复建议**: 添加 `@NotNull @Min(-3) @Max(6)` 和 `@Size(max=500)`，控制器参数加 `@Valid`。

### 缺陷 7 (高): @Async 审计日志不生效

- **位置**: `service/impl/TAuditLogServiceImpl.java:16`
- **影响范围**: 所有 `@AuditLog` 标记的接口响应延迟
- **问题**: 如 `known-issues.md` 4.1 节所述，`@Async` 加在 MyBatis-Plus `ServiceImpl` 子类上不起效（CGLIB 代理冲突）。审计日志写入同步阻塞 HTTP 响应，`auditLogExecutor` 线程池完全未使用。
- **修复建议**: 将异步保存逻辑提取到独立的 `@Component`（不继承 `ServiceImpl`），通过 Mapper 直接 insert。

### 缺陷 8 (高): 多个 Service 写操作缺 @Transactional

- **位置**: TCustomerServiceImpl, TBoardServiceImpl, TOffcutServiceImpl, TOrderItemServiceImpl, AlgorithmServiceImpl.submit()
- **影响范围**: 客户/板材/余料/订单明细写入
- **问题**: 上述实现类继承 MyBatis-Plus ServiceImpl 执行 save/update/delete，但未声明 `@Transactional`。MyBatis-Plus 基类操作使用自动提交，部分失败时无法回滚。
- **修复建议**: 在 `save`/`update`/`delete` 重写方法上添加 `@Transactional(rollbackFor = Exception.class)`。

### 缺陷 9 (中): RBAC 权限降级过于宽松

- **位置**: `interceptor/TokenInterceptor.java:51-56`
- **影响范围**: 数据库异常期间的权限控制
- **问题**: 权限表查询失败时，拦截器静默回退到 `List.of("*")` 通配权限，导致任何认证用户在数据库异常期间获得管理员权限。
- **修复建议**: 数据库异常时回退到 `List.of()`（拒绝所有），通过配置项 `rbac.fail-open: true/false` 由运维决定策略。

### 缺陷 10 (中): 审计日志可能记录敏感参数

- **位置**: `aop/AuditLogAspect.java:55`
- **影响范围**: 未来扩展风险
- **问题**: 审计切面无条件序列化所有请求参数存入数据库。当前 `@AuditLog` 端点不含密码字段，但如果将来在校验密码的接口上加 `@AuditLog`，密码将以明文入库。
- **修复建议**: 在 `toJsonString()` 中添加字段名过滤（如 "password"/"token"/"secret" 替换为 `***`）。

### 缺陷 11 (中): 历史密钥泄露残留风险

- **位置**: Git 历史 / `docs/known-issues.md:74-94`
- **影响范围**: 当前 JWT 安全性
- **问题**: 提交 `8b1aa0d` 修复了硬编码密钥问题，但需确认 JWT 密钥确实已轮换为新值，且旧密钥未残留在任何 Git 历史中。
- **修复建议**: 确认当前 `JWT_SECRET` 与泄露值 `xK7vN9mP2qR8tL5wY3nH6jB4cF1dG0sA9eU8iO7pM2k=` 不同；在 GitHub 上确认 `git filter-branch` 已覆盖所有历史。

### 缺陷 12 (中): TestController 命名不当

- **位置**: `controller/TestController.java`
- **影响范围**: 代码可维护性
- **问题**: 类名暗示为测试代码，实为算法求解入口 `POST /algorithm/answer`。与 `AlgorithmController` 共享 `/algorithm` 路径可能导致路由冲突。
- **修复建议**: 重命名为 `AlgorithmLegacyController` 或合并到 `AlgorithmController`。

### 缺陷 13 (中): AlgorithmController 强转具体实现

- **位置**: `controller/AlgorithmController.java:64`
- **影响范围**: 接口抽象
- **问题**: `algorithms()` 端点将 `AlgorithmService` 强转为 `AlgorithmServiceImpl` 调用未在接口声明的方法。如果 Spring AOP 代理了该 Bean，会产生 `ClassCastException`。
- **修复建议**: 将 `listAlgorithms()` 方法提升到 `AlgorithmService` 接口中。

### 缺陷 14 (中): 审计日志分页缺校验

- **位置**: `controller/AuditLogController.java:25-28`
- **影响范围**: 审计日志查询
- **问题**: `pageSize` 无 `@Max` 限制，攻击者可通过 `pageSize=1000000` 造成大查询。
- **修复建议**: 添加 `@Validated` + `@Min(1) @Max(100)` 约束。

### 缺陷 15 (中): 用户状态缺校验

- **位置**: `controller/UserController.java:55-56`
- **影响范围**: 用户管理
- **问题**: `accountStatus` 参数接受任意整数，超出 1-3 范围的无效值会被直接写入数据库。
- **修复建议**: 添加 `@Min(1) @Max(3)` 校验，或改用枚举参数。

### 缺陷 16 (中): 算法模块缺测试覆盖

- **位置**: `model/TabuSearch.java`, `model/GeneticAlgorithm.java`, `model/TabuMapTree.java`, `util/ReadDataUtil.java`, `service/impl/AlgorithmServiceImpl.java`
- **影响范围**: 核心业务逻辑质量保障
- **问题**: 系统最复杂的代码（禁忌搜索、天际线放置、多容器迭代、遗传算法）仅有一个 `AlgorithmUnitTest.java`，无覆盖 `ReadDataUtil.getSolution()`、`TabuMapTree`、`AlgorithmServiceImpl.doExecuteTask()`、多算法对比流程。
- **修复建议**:
  1. 补 `TabuMapTree` 单测（含缺陷 2 的回归用例）
  2. 补 `ReadDataUtil.getSolution()` 集成测试
  3. 补 `AlgorithmServiceImpl` 正常/异常路径测试

### 缺陷 17 (中): AuthController 全 HTTP 方法暴露

- **位置**: `controller/AuthController.java` — 使用 `@RequestMapping`（无 method 限制）
- **影响范围**: 认证接口
- **问题**: `/auth/login`、`/auth/register`、`/auth/logout` 接受所有 HTTP 方法（GET/POST/PUT/DELETE...），不符合 REST 惯例且扩大了攻击面。
- **修复建议**: 改为 `@PostMapping`（login/register）和 `@PostMapping`（logout）。

## 10. 常见问题排查

### 10.1 后端启动失败

**现象**: `Failed to determine a suitable driver class`

**原因**: `application.yml` 中 `datasource` 缩进不对，掉到了其他配置块下。

**解决**: 检查 `datasource:` 必须在 `spring:` 下，缩进严格对齐。参考 `docs/known-issues.md` 2.1 节。

### 10.2 中文乱码

**现象**: 日志中中文显示 `?` 或乱码

**解决**:
```powershell
chcp 65001
```
并在 `application.yml` 中确保：
```yaml
logging:
  charset:
    console: UTF-8
```

### 10.3 登录报 NPE

**现象**: `Cannot invoke "Long.longValue()" because "currentUserId" is null`

**原因**: 新增系统表未加入 `UserIdHandler.IGNORE_TABLES`，且在 TokenInterceptor 鉴权前被查询。

**解决**: 将表名加入 `UserIdHandler.java` 的 `IGNORE_TABLES` 列表。参考 `docs/known-issues.md` 5.1 节。

### 10.4 @Async 不生效

**现象**: 标了 `@Async` 的方法同步执行

**原因**: 如 `docs/known-issues.md` 4.1 节所述，`@Async` 不能加在 MyBatis-Plus `ServiceImpl` 子类上。

**解决**: 将异步方法提取到独立的 `@Component` 类中。

### 10.5 排样算法返回空结果

**现象**: 返回空 `Solution` 或无解

**可能原因**: 所有矩形尺寸均大于容器尺寸（含旋转后），或间隙导致无法放入。

**排查**: 检查输入数据 — 确保至少有一个矩形在旋转或不旋转的情况下能放入容器（长宽 + 间隙 ≤ 容器长宽）。

### 10.6 Maven 依赖缓存问题

**现象**: `mvn compile` 报依赖找不到

**解决**: 使用隔离本地仓库：
```powershell
mvn "-Dmaven.repo.local=target\.m2" compile
```
或清理全局缓存：
```powershell
Remove-Item -Recurse -Force $env:USERPROFILE\.m2\repository
mvn compile
```

### 10.7 小程序请求失败

**现象**: 小程序调用后端接口报错

**检查项**:
1. 微信开发者工具 → 详情 → 不校验合法域名（开发阶段）
2. `miniprogram/utils/config.js` 中 `baseUrl` 是否正确
3. 后端是否在运行且端口 8080 未被占用
